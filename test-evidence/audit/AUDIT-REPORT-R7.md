## 本轮修复

### F-3 · P1 · 遗忘后错误原因标注功能完全失效（双重缺陷）
- 现象：评「遗忘」后七类原因 chips 行从不出现（R3-R6 三轮尝试均失败，当时误判为环境问题）
- 根因 1（时序）：`rate(1)` 先置 `showErrTags = true`，紧接着 `await next()` 第一行就把它重置为 `false`——置位永远被清除
- 根因 2（键路径）：chips 渲染读 `t.errReasons[rid]`，但 errReasons 实际在 `review.ko` 段（`t.errReasons` 为 undefined）→ `undefined[rid]` 抛 TypeError → 渲染崩溃
- 修复：标注置位移到 `next()` 之后（errTagCardID 先行保存）；键路径改为 `t.review.ko.errReasons[rid]`
- 回归实测：遗忘后 chips 行出现（**记忆空白/概念混淆/条件遗漏/步骤错误/题面不清/来源过时/注意力中断** 七类全渲染）、点选后标注持久化（error-tags.json 写入 memory-blank ✓）、行自动隐藏
- 备注：动态键访问（`t.errReasons[rid]`）为静态 i18n 门禁盲区；本轮先例证明此类缺陷仍需 UI 实测兜底
