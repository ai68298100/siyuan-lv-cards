# R54 性能测量记录

测量日期：2026-10-14。工作区版本字段为 `0.209.3`，对照 Git 基线 `e5520b7`（v0.209.3）。环境为 Windows、本机 Node `v24.16.0`、pnpm `12.5.1`。这是一次本地测量，不代表思源宿主、Android 或其他设备的表现。

> 历史测量快照：文中“当前工作区”仅指 2026-10-14 的测量对象，不代表 v0.210.1；本轮未重新测量。当前发布验证见 [v0.210.1 验收报告](../release-v0.210.1.md)。

## 收件箱选择查询

复现命令：

```powershell
node scripts/benchmark-inbox-selection.mjs
```

脚本各执行 3 次预热和 9 次采样，取中位数。旧写法为 `visible.every(row => checked.includes(row.id))`；新写法每轮先构造 `Set(checked)`，再用 `has` 扫描可见项，因此计入 Set 构造成本。两种写法处理相同规模、全选命中的数据。

| 项目数 | `includes` 中位数 | Set 构建与查询中位数 | 测量结果 |
|---:|---:|---:|---:|
| 5,000 | 16.834 ms | 0.230 ms | 此微基准约快 73 倍 |
| 10,000 | 72.803 ms | 0.508 ms | 此微基准约快 143 倍 |

这是 Node 端的算法微基准，不包含 Svelte 响应式调度、DOM、样式、辅助技术或思源接口；不能据此推断页面 INP 或整体交互延迟。

## 生产构建

基线和当前工作区都执行 `pnpm build`，并对 `dist` 内全部 `.js`、`.css` 文件用同一 Node `zlib.gzipSync` / `brotliCompressSync` 默认设置计算压缩大小。构建时长各只测一次，受机器负载影响，不用于宣称构建速度变化。

| 范围 | 基线 `e5520b7` raw / gzip / Brotli | 当前工作区 raw / gzip / Brotli | 变化 |
|---|---:|---:|---:|
| `index.js` | 161,199 / 53,703 / 46,087 B | 162,442 / 52,130 / 43,916 B | gzip -1,573 B（-2.9%） |
| 全部 9 个 JS/CSS 产物（含 Kernel） | 752,154 / 230,718 / 199,497 B | 869,250 / 261,297 / 222,894 B | gzip +30,579 B（+13.3%） |
| 一次 `pnpm build` | 9.32 s | 8.67 s | 单次样本，不作性能结论 |

当前各页面 JavaScript chunk（不含对应 CSS）的 gzip：Hub `82,503 B`、复习 `40,775 B`、对话框 `67,182 B`。基线对应为 `62,553 B`、`38,197 B`、`61,805 B`。当前工作区同时包含 R54 界面、请求策略和多项功能实现，故这些总包变化不能归因于本轮性能优化；只能确认入口文件 gzip 小幅下降，不能声称应用总包变小或页面加载更快。

## 未测与暂缓项

| 项目 | 当前证据与处理 |
|---|---|
| 首屏 LCP、交互 INP、布局 CLS | 未在相同思源宿主和设备上测量，暂不声称改善 |
| 收件箱真实长列表滚动/渲染 | 只有算法查询微基准；缺浏览器长列表基线，暂不加虚拟滚动。管理器已有 20 条分页；固定行高可能破坏窄屏布局、焦点和滚动恢复 |
| 图片现代格式与响应尺寸 | 运行时图片取自思源块，没有本地可批量转换的图片集；icon/preview PNG 是集市元数据资源，格式转换需要兼容性验证 |
| 遮挡图片尺寸与 CLS | 当前实现仅在图片 load 后写入自然宽高，未测 CLS，也不能据此声称加载前已预留空间 |
| 字体子集化 | 未发现插件自带字体或 `@font-face`，无可子集化的字体文件 |
| 路由级分块 | Hub 内页面有源码动态导入，但发布 chunk 是独立 IIFE，内部导入会被打包器内联。进一步拆分需要验证 Svelte 运行时单实例与宿主加载协议，暂不做未经验证的拆分 |
