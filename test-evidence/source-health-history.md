# 维护页来源健康历史验收

日期：2026-10-16；版本：v0.209.5 工作树。

## 交付范围

- `source-health.json` 持久化问题发现记录及可选处理时间 `resolvedAt`；兼容旧记录，读取方获得副本。
- 扫描响应独立返回全部非空来源历史，包含已经不在卡组或本次扫描结果中的来源。
- 维护页独立折叠区按卡片显示历史；区分未解决与已解决/已确认，显示发现和处理时间。缺少或无效时间有文字兜底。
- 每张卡首次展示最近 20 条，可继续展开；相同时间/详情的多条记录不会产生重复渲染键。
- 人工确认当前来源后更新基线并保留历史，确认成功后重扫并展开历史；取消、保存失败和重试保留原有状态。
- 来源已经不在本次扫描中时，界面明确其历史状态未经本轮验证，不把旧记录当作当前健康结论。

## 修复的问题

1. 已处理来源问题不再因退出债务列表而失去历史查看入口。
2. 同卡多个来源问题合并为一条维护债务，逐项列出原因，消除 Svelte 重复键崩溃。
3. 确认来源不再把缺失或未知的媒体误标为已恢复；未知事实和来源删除不会顺带解决未经验证的旧问题。
4. 问题解决后再次发生会新增记录，保留各次发现和处理时间。

## 构建边界

完整治理检查发现累计改动使 shell gzip 超过既有 55 KiB 门槛。维护修复/近似重复、帮助文案、考试复盘渲染和诊断格式化改为通过现有 hub chunk 按需读取；纯函数跨 chunk，存储、事务适配器、事件和缓存仍由 shell 持有。

`smoke-dist` 实际执行生产 IIFE 产物，验证三 chunk 注册共存，并通过注册表执行修复预览/确认/写入、近似重复、双语帮助、带宿主过滤函数的复盘报告和诊断格式化。

服务契约不兼容会清除对应模块缓存、脚本、样式与注册项，允许修复部署后重试；帮助和诊断加载失败有可见错误反馈。已加入“旧模块已成功缓存→失效→修复重载”回归。

## 实际范围与后续

- 历史记录的是来源健康问题发现与处理，不是每一次来源编辑的审计，也不证明卡片知识内容正确。
- 没有既有指纹的旧卡不会因此自动获得“已验证健康”结论；不新增自动建立历史基线策略。
- 真实思源 Chrome 的普通/挖空/遮挡/导入/旧坏卡五路径验收尚未通过；此前会话没有可连接 Chrome，内核探测停在锁屏验证。自动化及产物验证不替代宿主走查。
- 此阶段发现维护扫描漏识别纯答案卡；2026-10-16 后续已统一结构门禁，详见 `maintenance-quality-gate.md`，仍不等同完整知识质量审核。
- 批修核心具有失败补偿和快照回滚能力，不代表界面已经提供已完成批次的撤销入口。
