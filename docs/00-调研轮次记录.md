## R48：AI 全局融入、思源 Agent 与可信运行（2026-10-02）

本轮根据“AI 必须进入总层面和细分层面”的新方向，重新扫描学习对象全生命周期和每个用户决策分支。重点不是再增加一个 AI 制卡入口，而是明确 AI 在捕获、澄清、建卡、练习、应用、维护中的角色边界，并把思源内置 Agent 作为优先宿主能力。结论如下：

- AI 输出必须经过任务模板、来源范围、上下文预算、结构 schema、质量检查和人工确认，才能形成候选对象；未确认内容不进入正式复习。
- 思源 Agent 需要按宿主版本协商 schema、工具效果、取消、流式和权限；旧版本或能力不足时降级到已有 AI API、本地模板或手工流程，不能注册假工具。
- 需要把提示注入、敏感信息识别、端点训练/保留策略、模型与提示词版本、成本/并发上限、脱敏 trace 和失败降级作为同一治理面，而不是由单个向导自行处理。
- 质量评估应分别测 groundedness、原子性、答案泄漏、重复、接受/编辑/拒绝、延迟、token/费用、隐私和学习结果证据；不能把生成成功、相似度或 retention 单独当作效果证明。
- 新增 BU-1—BU-42 的全局治理与 BV-1—BV-24 的模块 AI 任务，共 66 条。模块项覆盖材料价值扫描、目标澄清、卡型路由、干扰项、语言/媒体、复习导师、应用反馈、来源维护、课程/教师、统计和系列编排；均复用已有业务契约，按合并任务验收。
- 本轮重新读取官方 [前端 Agent 声明](https://github.com/siyuan-note/petal/blob/32afa1b6631d5a649456365fa5ca525c39c78a67/siyuan.d.ts#L887) 与 [Kernel Agent 声明](https://github.com/siyuan-note/petal/blob/32afa1b6631d5a649456365fa5ca525c39c78a67/kernel.d.ts#L599)，并用 Git main ref 核对提交 `32afa1b`。前端 `addAgentCapability`、Kernel `registerCapability/unregisterCapability` 和四类 effects 已有公开类型；流式、取消、主动启动 Agent 对话和权限强制仍需独立验证。
- 后续先建立 eligibility 检查、统一调用流水线、脱敏黄金样本、模型/提示词注册表和能力协商 fixture，再决定哪些 AI 功能进入实现窗口。
