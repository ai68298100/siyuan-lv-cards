# 39 - UI 精品化差距分析与批次计划（含 Anki 导入立项）

> 成文于 2026-10-05（v0.185.1 后），来源：用户反馈"目前 UI 效果与原型图相差甚远"触发的专项差距分析。
> 结论：差距真实存在且可定位到文件/行级，但**没有超出 docs/38 P1-A/P1-B 已识别范围**——本文档把差距具体化，
> 并给出可执行的批次切分。原型基准：docs/13（R52 线框）、docs/15（星轨视觉系统）、`docs/prototypes/starline-r52.html`（可交互评审稿，含全部 10 个任务面标记与可直接对照的 CSS）。

## 1. 原型核心要求摘要

1. **布局**：总览首屏"今日行动优先"——继续现场 hero 卡（上次停在哪/剩余/继续本场）→ 到期等少量统计 → 其他选择入口；统计与深度指标**渐进展开**（docs/13 §3、§1.3）。桌面内容宽约 **1200px**、24px 侧距；三层表面（中性背景/白色工作面/软提示面）。
2. **视觉**：品牌色占比 ≤10%，只强调当前状态与主动作；卡片圆角 12–16px、1px 派生边框、阴影只表层级；页题 24/700（docs/13 §1.3；docs/15 §2 写 20/700——**两文档口径不一致，需先裁决**）；展示数字 28–32/700 + tabular-nums。
3. **动效纪律**：**默认静态，无持续 breathe/glow/光泽扫过**（docs/15 §6；docs/13 §1.4 点名当前源码装饰性动效"不能视为 R52 已落地"）；动效仅 120/180/240ms 且 reduced-motion 全覆盖；完成态不以 pop/错峰遮挡收工。
4. **交互**：每阶段一个主动作；评分四档同级；六类状态（loading/empty/stale/error/unknown/partial）各有下一步，"未知不显示为 0"；图标可读、操作不依赖 hover；触控目标 ≥44px。
5. 评审稿 `starline-r52.html` L11-14 给出可对照样：`page-head`（eyebrow+24px 标题+描述+动作组）、`.panel`（16px 圆角 1px 边框）、`.hero`（brand-soft 底继续现场卡）、`.rating`（4 列/窄屏 2×2、77px 高）、`.study-card`（760px 居中、48/44px 内边距、min-height 300px）。

## 2. 差距清单（按类别，带证据）

### 2.1 布局结构（最大差距）

- **总览无"今日行动/继续现场"首屏**：`src/ui/dashboard.svelte:313-411` 首屏即 5–7 个统计卡横排，随后热力图/周对比/里程碑/保持率长列表——原型反对的"统计抢题面"；全文无 resume/继续现场状态，hero 卡不存在。
- **中心缺页头语义**：`src/ui/hub.svelte:162-165` 仅一条 pill 型 `LvTabs` 顶栏，无 `page-head` 结构；各子页标题风格不一。
- **整页缺失（规划态）**：T02 材料整理、T03 三栏审核、T08 待处理聚合、T10 演练工作面无对应组件；`ai-wizard.svelte` 仅配置/候选两画面。

### 2.2 视觉风格

- 令牌层已齐（`src/index.scss:7-44` 全套 Starline token 已实装），但页面参数未对齐：`.lv-page` max-width **1080px**（`index.scss:58`）vs 原型 1200px；页题 20px（`index.scss:74`）vs docs/13 的 24px。
- **违反自家动效纪律三处**：`.lv-dot` 默认 breathe 无限动画（`index.scss:172-184`）；`.lv-btn-primary` hover 光泽扫过（`index.scss:199-218`）；`lv-anim-glow` 用于复习揭晓（`src/ui/review.svelte:1349`）。
- inline style 未收敛：review.svelte 约 20 处、settings.svelte 9 处、dashboard 统计卡每张带 `min-width:140px` 内联（`:367-410`）。
- 图标可读性差：review 工具栏一排符号按钮 `≡ ⚙ ⟳ ? ↶ ✕`（`review.svelte:1339-1346`）；manager 的 ★/🗑（`manager.svelte:291,298`）。
- 语义混用：review 内用宿主 `b3-chip`（`:1331-1332`）而非自家 `lv-chip2`，同一组件两种皮肤。

### 2.3 交互反馈

- 完成页错峰入场 `lv-anim-rise` + pop 徽章（`review.svelte:1223-1256`），违反 docs/15 §6。
- 可点击 div 无键盘等价：`manager.svelte:352`（`role="presentation"` + onclick）。
- 六类状态不成体系：LvSkeleton/LvError/LvEmpty 已存在且 dashboard 已用（亮点），stale/unknown/partial 缺失；manager 无"匹配范围/总数"明示。
- 评分条接近规范（四档+kbd 预览）但缺窄屏 2×2 与 soft 语义色底；限时"遗忘"自动提交评分 1 是登记在案的差距（docs/13 §6）。

## 3. Anki `.apkg` 导入立项方案（2026-10-05 用户批准，Track F 首个解冻项）

**定位**：迁移获客——把 Anki 用户的牌组、媒体与学习史低损失搬进小驴闪卡；正式调度仍归内核 riff/FSRS（ADR-3），导入的 revlog 只作历史展示，不冒充本插件调度记录。

**范围（对齐 docs/38 P2-1）**：`.apkg` 解包（SQLite + media manifest + zip）→ 两阶段导入（先解析预览、后确认落库）→ 字段/模板映射（HTML 清洗为思源块）→ 媒体导入与缺失降级 → 复习历史映射（revlog 近似换算）→ 重复检测（块指纹+内容哈希）→ 损失报告（每张卡：丢了什么、为什么、去哪看）→ 幂等（同包重导不重复建卡）。

**里程碑**（每片都可独立验收，纯逻辑先行）：

- **M1 解析器纯模块**：`core/anki-package.ts` 零依赖解析 `.apkg`/`.colpkg` 结构（notes/cards/revlog/models），+完整单测（用脱敏样例包 fixture）；不触 UI。
- **M2 映射与预览**：字段映射规则、HTML→块 markdown 清洗、重复检测、导入预览报告（纯模块+单测）。
- **M3 导入执行**：落库（建卡 API 批量+断点续传）、媒体文件写入、进度与失败恢复（接 shell，UI 最小可用）。
- **M4 损失报告与导出**：损失报告页、幂等重导、（可选）`.apkg` 导出。

**排期约束**：让位于 UI 精品化批 1（视觉纪律）；M1 可与批 1 并行（纯模块互不干扰）。
