> 调研日期：2026-10-02。本文只记录产品研究、证据边界和规划待办，不授权本轮开发。当前基线为 v0.63.0；代码、CI、内核唯一调度源等事实沿用 [00-调研轮次记录](./00-调研轮次记录.md) 与 [25-多维调研与生态联动](./25-多维调研与生态联动.md)。
>
> 第三轮新增 AY-BG 共 **125 条候选待办**，与上一轮新增 88 条一样，包含把历史总项拆成可验收场景的条目，不等于 125 个独立开发工作包。它们分为：知识创作 15、语言材料 16、课程长期学习 16、应用练习 12、内容生命周期 14、用户研究 14、宣传上架 13、系列联动 13、平台长期运行 12；实际合并交付必须按关联项和内核契约分批进行。

## 一、这轮调研回答的产品问题

过去的待办已经覆盖复习页、制卡、管理器、统计、考试、AI、性能、UI 和联动接口，但仍有几个产品层空白：

1. **材料如何变成可维护的知识**：竞品的重点不只是生成一张 Q/A，而是保留概念、属性、字段、上下文、引用、模板和个人修改的身份。小驴需要先定义内容身份，再决定是否生成卡片。
2. **记住以后如何应用**：AMBOSS 将卡片、术语解释和题库入口放在相邻流程；UWorld 支持从题目解析追加到已有卡，并区分同题卡、相关卡和最近卡；Execute Program 用解释、代码练习和后续短复习承接概念。适配小驴时，应用练习必须是独立记录，复习调度仍归思源内核。
3. **阅读和语言学习不是普通 TTS**：Migaku、LingQ、Readlang、Language Reactor、Clozemaster、WaniKani 和 jpdb 分别处理词形/词义、例句、字幕时间点、真实音频、听力揭示、阅读准备度和学习任务。小驴当前的 `q/a/d` 与字符串 LCS 不足以表达这些对象。
4. **课程学习需要目标、材料、检查和返场**：Quizlet Study Guides、Khan Academy 的课程/单元目标、Google 2026 Study notebooks 的诊断→分段课程流程、Goodnotes 的 Study Set/Smart Learn 与 Practice Mode，都说明“完成一次复习”不等于“完成一个学习目标”。这些流程只能提供导航和证据，不应伪造掌握率。
5. **内容发布以后仍然会变**：Mochi 的字段/模板与导出、AnkiHub 的受保护字段、Anki 导入更新、Zotero 的摘录回引、Hypothesis 的标注导出，以及 UWorld 的“追加到已有卡”都指向版本差异、个人字段保护、引用闭包和可回滚更新。
6. **产品研究必须验证真实阻断**：竞品资料是问题线索，不是小驴用户需求的证明。第三轮新增独立用户研究、可用性测试、指标定义和停止条件，避免把待办数量继续当成路线图优先级。

## 三、产品机会的组合方式

| 方向 | 用户场景 | 小驴候选能力 | 必须先确认的边界 |
|---|---|---|---|
| 知识创作 | 概念、列表、表格、代码、术语 | 字段、上下文、模板、来源和变体预览 | 不把块结构直接当内核 note schema；V2/Legacy 降级 |
| 语言与阅读 | 查词、例句、字幕、听力、阅读准备 | 词条/sense/occurrence、时间锚点、分层提示 | 词汇状态不等于卡片掌握；媒体必须有用户授权 |
| 课程与考试 | 考纲、章节、基线、应用、返场 | 学习包、目标矩阵、独立练习和计划入口 | 目标完成不折算 FSRS；考试正式题库仍归考试模块 |
| 内容维护 | 共享包更新、个人备注、引用失效 | 差异、字段保护、收件箱、可回滚导出 | 稳定 ID 与字段所有权优先；不要静默覆盖 |
| 研究与转化 | 首次复习、长期留存、安装决策 | 访谈、可用性测试、公开案例、上架素材 | 不采集原文/密钥；不以打开率宣称学习效果 |
| 系列协同 | 拾遗→闪卡→复习→打卡、考试错题 | 版本化事件、能力探测、幂等、回链 | 外部插件失败不能阻塞核心复习；用户逐次授权 |
| 长期运行 | 移动后台、断网、时区、恢复 | 可取消、可恢复、冲突合并、清理预览 | 数据生命周期和内核所有权不可混淆 |

## 四、第三轮优先研究顺序

1. 先验证 **内容身份**：AY-1、AY-4、AZ-1、AZ-8、BC-3。没有 source/sense/field/version 的定义，后续模板、语言、共享和联动都会重复建卡。
2. 再验证 **真实任务**：AZ-2、AZ-9、AZ-11、BA-2、BA-5、BB-1；用可用性测试判断哪些是高频阻断，不能凭竞品数量排期。
3. 然后验证 **维护与恢复**：BC-2、BC-4、BC-8、BG-5、BG-12；用户信任来自可解释的更新、删除和回滚。
4. 最后决定 **传播与联动**：BE-1、BE-5、BF-1、BF-3、BF-6。没有能力状态、隐私和失败降级，不能把跨插件旅程写成市场承诺。

## 五、明确不应从竞品资料直接推出的结论

- 不因为产品写了“AI optimized”“science-backed”或用户反馈正面，就声称小驴能提升记忆效果；所有保持率、覆盖率和掌握率必须有口径、样本和未知状态。
- 不因为竞品有学习算法，就在插件内再实现 FSRS、语言学习调度或考试调度；正式 due、评分和间隔继续由思源内核负责。
- 不因为能读取文本，就默认能读取流媒体、联系人、付费题库或整个笔记本；捕获、AI 外发、媒体和跨插件都要逐次授权。
- 不因为能导出 Markdown/CSV，就声称能完整往返模板、媒体、历史和复习状态；导出必须展示损失和可恢复范围。
- 不因为一次访谈或一个 GitHub issue，就把候选项提升为 P0；先记录证据等级、反例、验证任务和停止条件。

## 六、第五轮定向缺口扫描

第四轮的纵向模型解决了单个学习者“目标→复习→应用→维护”的闭环，但产品要成为全域学习平台，还需要补齐横向角色和可信度边界：

- **知识发现**：从问题出发检索来源，保存 Claim–Evidence–Occurrence，处理矛盾、时效、许可和未知缺口，再决定是否进入候选卡；
- **作者与教师**：把内容创作、质量闸门、版本发布、班级分发、学生反馈和聚合统计与个人学习历史隔离；
- **系列编排**：共享目标身份、Today 任务、事件死信、部分成功补偿和隐私范围，避免多个插件各自发通知或形成事件回环；
- **长期信任**：把商业成本、市场包供应链、许可证、隐私请求、第三方扩展和效果声明纳入可审计产品能力；
- **结果证据**：将前置依赖、误解、学习负担、知识可信度与回忆/应用结果分轴记录，不把卡数、连击或 AI 相似度当掌握证明。

这些结论形成 [17-待办清单](./17-待办清单.md) 的 BO-BT 共 44 条候选项，仍需按能力矩阵、真实用户任务和宿主/外部依赖分阶段验证；本轮不授权开发。
