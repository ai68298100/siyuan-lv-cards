## 二、按完整使用流程找缺口

### 1. 从安装到第一次复习

现有入口很多：顶栏、块菜单、命令面板、面包屑、onboarding、AI 向导、考试页。流程问题在于入口上下文不总能传到下一步：通知目前只打开插件自定义复习页；官方最新 V2 `openTab(card)` 类型新增范围和查询字段，而本地 SDK 仍为旧字段，应先确认宿主支持再接入。首次启动还需要验证跳过、完成、宿主 X、Esc 的关闭责任是否一致。

### 2. 制卡到可复习

块制卡、快速制卡、标记符和 AI 制卡都可能产生普通文档与内核卡两层状态。用户需要知道“草稿、已写入文档、已加入卡组、可出现在队列”分别代表什么；失败重试不能重复建卡或留下孤儿文档。拾遗已有摘录制卡入口，闪卡应复用稳定来源标识和回链，不应另建一套“待制卡箱”事实源。

### 3. 复习中断到恢复

AQ-1/AQ-2 已确认会话恢复与按钮/快照时序问题。本轮进一步把体验验收拆成：弹窗生命周期、请求竞态、同步重载、评分成功/失败、关闭/再来一批、焦点回归。每个节点都需要可观察状态，不能用“页面看起来还在”代替数据确认。

### 4. 复习结果到统计、打卡和报告

统计、角标、考试计划、学习报告、打卡事件都消费复习结果；如果没有事件 ID、来源、时间精度和幂等键，多处消费会重复计数。小驴打卡 API v5 要求稳定 `source + externalRef`、可重试且原始 externalRef 保留；应先建立跨插件事件映射，再决定哪些结果可写入打卡。

## 五、排期原则

1. 先修 P0 的流程阻断和事实错误，再做可见功能；
2. P1 先解决数据一致性、密钥、跨前端、V2 能力和弹窗生命周期；
3. P2 以能力探测、预览、可撤销和降级为前提，不把设备/内核不支持的能力写成宣传承诺；
4. 每个系列联动都要有正式契约、稳定 ID、幂等键、dispose 和隐私边界；
5. 每个性能数字都要写明设备、思源版本、卡量、网络和测量方法；
6. 每个市场文案都从同一状态源生成，能回链到代码、真机记录或 fixture。

## 八、实施边界

- 不在插件内重做 FSRS、队列、sibling bury 或 V2 迁移状态；这些由内核 Gateway 决定。
- 不依赖小驴系列的私有 DOM、内部 JSON 或未发布事件；没有正式 API 时只做导出/导入或用户确认的通用捕获。
- 不默认把复习一次写成打卡一次；写入打卡必须经过用户明确开启、能力协商和可追溯 externalRef。
- 不因竞品有 PDF、社区卡包或 AI 导师就直接承诺同等能力；先完成来源、隐私、失败恢复和成本边界。
