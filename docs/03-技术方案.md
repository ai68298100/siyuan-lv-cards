# 小驴闪卡 · 技术方案

> 基座：官方模板 `plugin-sample-vite-svelte`（Vite 8 + Svelte 5 + pnpm，Node ≥ 24）。命名：中文 **小驴闪卡**，英文 **Lv Cards**，插件名/仓库名 `siyuan-lv-cards`。

## 1. 架构总览

```
src/
  index.ts            # LvCardsPlugin：生命周期、顶栏/Dock/命令注册、模块装配
  core/
    modules.ts        # 模块注册表（大杂烩的开关骨架）：id/名称/默认开关/init/dispose
    settings.ts       # 设置持久化（loadData/saveData）、默认值、迁移
    revlog.ts         # 本地复习日志（评分事件追加写 JSONL），统计与热力图数据源
    fsrs-shadow.ts    # ts-fsrs 影子引擎：由 reps/lapses/lastReview 估算 S/D，算保持率
    exam.ts           # 考试 deadline：倒排每日应学曲线
  api/
    riff.ts           # 内核 17 个 /api/riff/* 端点的类型化封装（fetchSyncPost）
    conf.ts           # FSRS 三参数 + 每日上限读写（/api/setting/*）
    sql.ts            # SQL 查询（blocks/cards 元数据、失效卡扫描）
  ui/
    dashboard.svelte  # 统计仪表盘（Tab）：总览卡 + 热力图 + forecast + 卡组对比
    manager.svelte    # 闪卡管理器（Tab）：跨卡包列表、搜索、批量操作
    review.svelte     # 复习面板（v0.1 先做评分+NextDues 预览；后续长成全功能面板）
    settings.svelte   # 设置面板：模块开关、FSRS 参数、考试模式、每日目标
public/i18n/          # zh-CN / en
```

## 2. 关键技术决策

> ⚠️ **2026-10-01 修订（内核 V2）**：官方 `feature/flashcard` 分支（3.9.0）新增 42 个 `/api/flashcard/*` 端点与旧 riff 兼容层，详见 `05-内核闪卡V2重构调研与应对.md`。由此：
> - 新增 **`src/api/flashcardV2.ts`**：V2 端点封装 + `getMigrationStatus` 能力探测（启动时一次，缓存 Legacy/Preparing/Active/LegacyDiverged 状态）
> - **双 API 轨制**：V2 Active 时优先 `startSession/getSessionQueue/reviewCard/undoReview`（会话复习）、`queryCards`（AST 搜索）、`getStatistics`（统计）；riff 层保留兜底（官方 legacy_compat 承诺兼容）
> - **影子 FSRS 作废**：V2 ReviewState 直出 Stability/Difficulty
> - **题型走官方 V2 卡型注册**（`registerFlashcardV2PluginType`，sourceType=`plugin:lv-cards:*`），不自建题型渲染栈

1. **调度绝不自建**：评分走 `reviewRiffCard`（Rating 1-4），到期走 `getRiffDueCards` 系列。插件是"驾驶舱"，与内核升级零冲突（ZY 已验证该路线稳健）。
2. **数据分层**：
   - 卡片本体 = 思源块 + riff 库（用户可见，不锁数据）
   - 插件私有 = `loadData/saveData`（模块开关、每日目标、考试配置、本地 revlog JSONL）
3. **本地 revlog**：内核不向插件暴露复习历史 → 插件在 `eventBus` 监听 `click-flashcard-action`/`updateCards`（ZY 验证过的广播），加上自研面板的评分事件，**从启用日起**追加记录；统计分"完整数据期/估算期"两段展示，诚实标注。
4. **影子 FSRS**：riff API 不暴露 Stability/Difficulty → 用 ts-fsrs 由 `reps/lapses/state/lastReview` 估算初值，仅供统计与 forecast 展示；预测值与内核调度如有偏差，以内核为准。
5. **优化器闭环**：优先尝试 ts-fsrs 官方 `binding`（WASI）在插件内跑优化；不可行则降级"导出 CSV → fsrs4anki 网页版 → 粘贴权重 → 一键写回"。
6. **UI**：全 b3 CSS 变量与内置组件类；图表用轻量自绘 SVG（热力图/柱状图）避免引重依赖；框架沿模板 Svelte 5。
7. **模块开关骨架**（大杂烩不臃肿的关键）：`core/modules.ts` 注册中心，每个功能模块声明 id/默认开关/装载条件；设置面板一键开关；禁用模块不注册 UI 入口、不产生后台开销。

### 2.1 AI/Agent 统一执行面（规划）

规划要求 AI 请求不再由 `ui/ai-wizard.svelte` 或其他页面直接拼接。目标执行链为：`TaskRegistry → ContextPack → PromptRegistry → ProviderRouter → SchemaValidator → EvidenceStore → AuditSink`。当前 v0.63.0 仍由 `index.ts` 制卡回调组织提示并调用 `api/ai.ts`，统一执行面尚未实现。思源 Agent 负责意图理解和受限工具编排，插件负责事实源、权限、引用、结构校验、候选预览、确认写入和撤销；自定义端点、本地模型和思源 AI 是规划中的可探测 provider 类型。

`ai-batches` 继续保留批次兼容，但新增的 `AIInvocation` 记录任务、输入范围 hash、同意、模板/模型版本、状态、用量、错误和用户确认。正式 rating、due、revlog、来源删除和跨插件外发不属于 AI 直接写权限。无 Agent API、无模型、断网、拒绝外发或达到预算时，统一降级到草稿、规则/本地模板或手工路径。

## 3. 内核 API 速查（已核实源码）

- 卡包：`createRiffDeck{name}` / `renameRiffDeck{deckID,name}` / `removeRiffDeck{deckID}` / `getRiffDecks{}`
- 加删卡：`addRiffCards{deckID,blockIDs[]}` / `removeRiffCards{deckID,blockIDs[]}`
- 到期队列：`getRiffDueCards{deckID,reviewedCards?}` / `getTreeRiffDueCards{rootID,…}` / `getNotebookRiffDueCards{notebook,…}`；响应含 `cards[]{cardID,blockID,lapses,reps,state,lastReview,nextDues{1..4}}` 与 new/old 计数
- 评分：`reviewRiffCard{deckID,cardID,rating(1-4),reviewedCards?}` / `skipReviewRiffCard{deckID,cardID}`
- 浏览：`getRiffCards{id?,page,pageSize}`（全局/树/笔记本三态）、`getRiffCardsByBlockIDs{blockIDs[]}`
- 干预：`resetRiffCards{type(0/1/2),id,deckID,blockIDs?}`、`batchSetRiffCardsDueTime{cardDues[]{id,due}}`
- 配置：`/api/setting/getConf`、`/api/setting/setConf` 中 `flashcard` 节点（NewCardLimit/ReviewCardLimit/ReviewMode/RequestRetention/MaximumInterval/Weights + 7 种制卡开关）

## 4. 兼容与风险

| 风险 | 应对 |
|---|---|
| 官方未来内置统计/管理器 | 保持轻量、数据不锁死；差异化走题型/AI/考试/游戏化组合拳 |
| `api:"optional"` 契约校验严格（page 必填等） | api/riff.ts 全部按 apicontract 精确建模，字段名驼峰 |
| 加密笔记本（encrypted box）不可拉卡 | getNotebookRiffCards 会报错 393，UI 提前过滤 |
| revlog 本地数据与多设备同步冲突 | JSONL 追加式 + 按时间戳合并；冲突取并集 |
| 移动端性能 | 标签/卡组统计缓存 60s（对齐 ZY 经验），并发上限 移动 4 / 桌面 8 |
