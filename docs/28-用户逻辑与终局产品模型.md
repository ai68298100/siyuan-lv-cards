# 小驴闪卡 · 用户逻辑与终局产品模型

> 版本：产品模型 v1.0（2026-10-02）
>
> 本文继续细化[产品使命与全功能战略](./27-产品使命与全功能战略.md)。重点不是再列竞品按钮，而是回答：用户为什么打开小驴、下一步要做什么、什么时候应该停止、如何知道自己真的学会了，以及多年以后如何继续维护这些知识。本轮仍只扩充产品规划，不开发代码。

## 1. 最终目的

用户不是为了拥有卡片而来，而是为了在未来某个场景中可靠地回忆、解释、判断和行动。闪卡只是把知识送入未来场景的中间载体。小驴闪卡最终要帮助用户形成**可调用的长期能力**，而不是积累更多卡片、刷出更长连击或得到更高的单一保持率。

一个知识对象只有在以下链路中逐步通过，才算完成学习闭环：

> **材料被发现 → 值不值得学被判断 → 内容被理解 → 事实被组织成合适卡片 → 在正确时间主动回忆 → 在新情境中应用 → 结果被反思 → 内容和计划被长期维护。**

因此最终产品同时追求六个结果：

1. **记得住**：正式复习由思源内核调度，卡片和评分有可靠历史。
2. **用得上**：用户能解释、辨析、迁移、解决问题或完成真实任务。
3. **找得到**：每个结论都能回到来源、章节、版本和个人上下文。
4. **改得动**：材料、卡片、字段、模板、计划和共享版本可以安全更新。
5. **负担得起**：系统根据时间、目标和精力帮助取舍，不制造无意义积压。
6. **带得走**：用户可以导出、迁移、恢复、暂停或更换工具，不被插件锁定。

## 2. 用户的真实决策链

用户不会按“模块菜单”思考，而是围绕一个目标做连续决策。产品要在每个决策点提供下一步，而不是把用户丢到空白页面。

| 决策阶段 | 用户心里的问题 | 产品必须提供的判断 | 失败时的退路 |
|---|---|---|---|
| 触发 | 我为什么现在学习？ | 目标、截止时间、材料、可用时间和当前状态 | 只记录目标或稍后开始，不强迫建卡 |
| 取材 | 这份材料值得放进系统吗？ | 来源范围、版本、许可、重复内容和预估投入 | 只保存来源，不生成卡 |
| 筛选 | 哪些内容值得长期记？ | 重要性、频率、先决知识、应用价值和用户选择 | 丢弃、暂存、标记稍后 |
| 理解 | 我是在背句子还是理解概念？ | 解释、例子、反例、上下文、术语关系和疑问 | 回来源、请教、建立理解笔记 |
| 创作 | 这张卡考什么能力？ | 题面、答案、提示、解释、引用、题型和变体 | 保存为普通笔记或候选，不进队列 |
| 启动 | 现在应该学哪些？ | 目标、到期、投入、材料难度和时间预算 | 只做短练习或安排稍后 |
| 回忆 | 我是真的会，还是刚看过？ | 先回忆、再提示、再揭晓；记录提示和信心 | 标记原因，回到解释/来源/应用 |
| 应用 | 换个情境还会吗？ | 案例、对照、生成、步骤、代码、语言输出或真实任务 | 保存疑问，不伪造正确率 |
| 收工 | 今天做到什么程度？ | 目的是否完成、剩余负担、疲劳、下一步 | 正常结束并保留现场，不制造失败感 |
| 返场 | 中断后还值得继续吗？ | 目标是否变化、材料是否过时、计划是否可行 | 只读浏览、重建目标或归档 |
| 维护 | 这条知识现在还可靠吗？ | 来源版本、个人修改、冲突、重复和失效链接 | 保留历史、标过时、人工合并 |

### 六个高频决策分支

| 触发 | 默认分支 | 必须保留的选择 |
|---|---|---|
| 划线/摘录进入 | 查阅→保存来源→候选整理→正式卡 | 默认不直接进入 due |
| 打开今日入口 | 正式到期、纯练习、应用任务或维护任务 | 用户确认模式，缺数据显示未知 |
| 评分后不确定 | 标疑问→查看解释→修订内容→下次正式复习 | 解释与评分分开 |
| 来源发生变化 | 查看差异→保护个人字段→更新原卡/新变体/归档 | 历史可追溯、操作可撤销 |
| 长期离开后返回 | 原计划、缩小范围、维护、封存或重建 | 不自动补齐全部逾期 |
| 联动失败 | 核心本地动作完成→事件待发送→重试/跳过/撤销 | 外部插件不可用不能阻塞复习 |

### AI 介入时的六个判断

AI 在每个分支都应先回答“是否需要、使用哪份材料、要产生什么对象、谁来确认、失败后怎么办”：

| 用户动作 | AI 的合适角色 | 用户必须看到/决定 |
|---|---|---|
| 捕获一段材料 | 提取术语、问题和候选重点 | 外发范围、来源位置、许可和是否进入收件箱 |
| 解释一个概念 | 基于授权来源给出分层解释、例子和反例 | 引用、未知项、语言/难度，不能把解释当事实证明 |
| 批量建卡 | 按任务模板生成候选并做质量检查 | 题型、数量、成本、逐卡接受/编辑/拒绝，未审不进正式队列 |
| 今日复习遇到困难 | 给提示、追问或旁路练习 | 是否揭示答案、是否进入正式评分、是否保存错因 |
| 应用任务结束 | 比对要点、提出补练建议 | 真实产出和专业判断，AI 相似度不能替代结果证据 |
| 来源或卡片变旧 | 找受影响对象、给差异和修订候选 | 版本、冲突、个人字段、发布/删除和回滚 |

AI 输出必须落在“候选→人工确认→可追溯对象”的路径中。思源 Agent 可以执行读取、筛选、准备和打开范围等受限工具，但工具调用次数、数据范围和写入效果要在用户可见的授权内；任何会改变内核评分、due 或对外分享的动作都要回到明确确认流程。AI 失败时保留当前材料和草稿，按已授权的本地模型、模板或手工路径降级；不可把取消、隐私拒绝、配额耗尽和模型不确定伪装成成功。

## 3. 用户状态模型

同一个内容不能只用“有没有卡”表示。产品应区分内容生命周期和学习生命周期：

```text
来源材料
  ├─ 未筛选 → 暂存 → 已选中
  ├─ 理解中 → 有疑问 → 已解释
  └─ 候选卡 → 已审核 → 已入库 → 正式复习
                                      ├─ 已应用/已验证
                                      ├─ 需修订/来源变化
                                      ├─ 暂停/暂缓
                                      └─ 过时/归档
```

这些状态不能互相冒充：

- “已阅读”不等于“已记住”；
- “卡片成熟”不等于“会应用”；
- “任务完成”不等于“考试掌握”；
- “来源更新”不等于“旧卡错误”；
- “暂停学习”不等于“删除历史”。

产品对象应逐步从单一 `Card` 扩展为 `Learning Object`：它包含来源、学习意图、概念/变体、练习证据、正式调度投影、应用反馈、维护状态和权限/许可；`Card` 是这个对象面向内核正式复习的一种投影。

三层状态机必须分开：

1. **学习对象**：captured → clarified → candidate → committed → practiced → applied → maintained → stale/retired；
2. **用户目标**：unbound → declared → active → paused → achieved/changed/abandoned；
3. **会话**：ready → in_progress → waiting_dependency → interrupted → resumable → completed/failed_recoverable。

每次状态迁移都记录 actor、原因、来源、时间和可逆性。跨层只发事件，不能直接篡改另一层事实：暂停目标不等于暂停全部卡，来源过时不等于用户遗忘，纯练习完成不等于 FSRS 复习完成。

产品承诺还要区分四类事实：**内核事实**（due、rating、revlog）、**内容事实**（来源、版本、许可、结构）、**用户事实**（意图、选择、信心、原因）和**结果证据**（回忆、解释、应用、迁移）。推荐、统计和宣传不得跨事实区猜测。

## 4. 六种主模式

一个入口可以根据用户目的进入不同模式，但每种模式都要说明是否读取/写入内核调度。

| 模式 | 适合什么时候 | 核心动作 | 正式写入 |
|---|---|---|---|
| **探索** | 刚接触材料、查词、读文档 | 浏览、标注、解释、收集问题 | 来源/摘录，可选候选；不评分 |
| **构建** | 决定长期记忆内容 | 原子化、字段化、模板化、审核和入组 | 创建/更新卡片，未评分 |
| **复习** | 到期或计划中的主动回忆 | 翻面、评分、撤销、改期、恢复 | 内核 rating/due |
| **练习** | 需要多次尝试或换题型 | 听力、打字、选择、案例、代码、白板 | 默认旁路记录，可选择提交正式评分 |
| **应用** | 验证迁移和实际能力 | 解决问题、解释、生成、操作、语言输出 | 任务/证据/反思，不自动改 due |
| **维护** | 更新、迁移、清理和返场 | 比对版本、合并字段、修复来源、暂停/归档 | 内容/计划/迁移状态，需明确影响 |

## 5. AI 在用户决策链中的位置

AI 应在每个模式提供“可审阅副驾驶”，减少认知负担并增加可验证性：

| 用户阶段 | AI 可以做 | 用户必须确认 | 事实/内核边界 | 无 AI 时的路径 |
|---|---|---|---|---|
| 捕获 | 分类、去重、问题提取、许可提醒 | 是否保存、是否外发 | 只写来源/候选 | 手工保存和筛选 |
| 理解 | 解释、例子、反例、前置关系 | 是否接受解释与引用 | 材料不足显示未知 | 回来源、查阅和手写备注 |
| 创作 | 选卡型、拆原子事实、生成题面和 rubric | 逐卡审阅、编辑、接受或拒绝 | 不直接进入 due | 手工制卡模板 |
| 回忆 | 分层提示、苏格拉底追问、错误原因候选 | 是否看提示、如何评分 | 不写正式 rating | 普通翻卡和自评 |
| 应用 | 生成案例、变式和反馈建议 | 目标、答案和应用证据 | 任务证据独立保存 | 手工案例与 rubric |
| 维护 | 重复/泄漏/过时检测、版本影响解释 | 合并、修订、归档或撤销 | 不静默覆盖历史 | 管理器 diff 与批量操作 |
| Agent | 理解意图、准备筛选和动作计划 | 每个写入/外发点 | 与 UI 共用权限和审计 | 命令面板与普通 UI |

AI 输出在学习对象上只能产生 `ai_proposed` 投影；用户确认后才转为 `human_verified` 或其他内容状态。`AIInvocation` 要记录模板、模型、输入范围、证据、用户编辑和确认，模型更新不能覆盖旧结果。AI 减少的是查找、组织和解释成本，增加的是来源可见、未知可见和决策可撤销；生成张数、相似度和单次正确率都不能代替学习结果。

## 6. 功能深度标准

以后新增一个功能，不只问“有没有”，还要回答五层问题：

1. **入口层**：用户在什么上下文里遇到它？是否保留当前文档、卡片、选区和目标？
2. **决策层**：系统要用户确认什么？哪些可以默认，哪些必须预览？
3. **内容层**：产生什么对象、身份、来源、版本、字段和关系？
4. **学习层**：它考哪种能力？正式评分、旁路练习、任务证据和反思如何区分？
5. **生命周期层**：如何更新、撤销、分享、迁移、删除、恢复和降级？

只有具备这五层，功能才算产品能力；只有一个按钮或一个 API 调用，仍属于技术素材。

## 7. 最终效果如何判断

小驴不以“卡越多越好”作为目标。长期产品指标应分为四类：

| 指标层 | 观察什么 | 不应该推断什么 |
|---|---|---|
| 记忆 | 回忆结果、间隔、提示使用、遗忘原因、内核历史 | 不能把单次正确当永久掌握 |
| 迁移 | 新情境解释、辨析、步骤、代码/语言输出、任务证据 | 不能把自由回答自动判成专业正确 |
| 系统 | 来源可追溯、重复率、内容修订、恢复成功、同步冲突 | 不能把功能使用率当学习效果 |
| 人因 | 时间预算、负荷、主动暂停、返场率、用户信任 | 不能用连击、XP 或通知打开替代学习成果 |

## 8. 后续规划方法

- 每个能力先放入用户决策链，说明触发、前置、下一步和退路；
- 每个深层功能先定义对象和状态，再设计 UI；
- 每个练习先声明是否写内核评分，避免旁路练习污染正式调度；
- 每个自动化先提供预览、取消、重试、幂等和恢复；
- 每个后置能力都登记依赖、替代路径和复评条件；
- 每轮产品研究优先合并重复条目、删除没有用户价值证据的条目，再增加新功能。
