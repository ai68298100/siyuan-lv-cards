# 小驴闪卡 · 产品使命与全功能战略

> 版本：战略基线 v1.0（2026-10-02）
>
> 本文把“小驴闪卡要成为多全面”说清楚。它是产品方向和范围文档，不代表 v0.63.0 已经实现全部能力；具体实现状态以待办清单、版本说明和真机验收证据为准。

## 1. 产品使命

**小驴闪卡的长期目标，是成为思源笔记中的全域学习操作系统与最完整的闪卡平台。**

**AI 与思源智能体是实现这一目标的核心能力。** 从材料理解、问题澄清和卡片创作，到对话练习、真实应用、内容维护和系列编排，每个能力域都要同时设计 AI 工作方式、用户决策、来源证据和手工路径。AI 的价值在于减少认知负担、提高内容质量，并帮助用户在未来场景中可靠回忆、解释、判断和行动。

它要把用户接触知识后的完整过程连起来：

> **发现材料 → 捕获内容 → 理解知识 → 组织结构 → 生成卡片 → 选择练习方式 → 交给内核复习 → 应用于课程/考试/工作 → 统计与反思 → 更新、分享和长期维护。**

“闪卡”是核心载体，但产品边界不止翻卡和评分。只要一个能力能让用户更容易把知识变成可理解、可练习、可复习、可应用、可维护的学习对象，就属于小驴的长期目标。它可以来自 Anki、RemNote、Quizlet、Mochi、Obsidian、语言学习工具、考试平台、阅读工具、专注工具和小驴系列插件；吸收机制时重新设计为思源本地工作流，而不是照搬品牌界面或调度算法。

一句话定位：

> **小驴闪卡：思源的全域学习操作系统——让任何知识材料都能进入一条可追踪、可复习、可应用、可长期维护的学习闭环。**

## 2. “最全面”的含义

全面不是把按钮堆在一个页面，也不是承诺一次版本覆盖所有竞品。全面指的是能力矩阵完整、模块之间连得起来、每项能力有清晰的数据身份和降级路径。

| 能力域 | 长期覆盖范围 |
|---|---|
| 材料进入 | 思源块、文档、选区、剪贴板、Markdown、CSV/TSV、Anki 包、PDF/图片/音频/字幕、系列插件摘录和用户授权的外部材料 |
| 内容创作 | 问答、双向、挖空、列表、表格、图片遮挡、代码、公式、音频、语言例句、字段/模板、概念属性和 AI 辅助制卡 |
| 复习练习 | 翻卡、打字、听写、选择、配对、遮挡、限时、滑卡、白板/手写、原音听力、应用题、反思题和纯练习模式 |
| 调度与计划 | 内核 FSRS、范围、考试倒排、课程目标、负荷、休息、返场、cram、优先级和多项目入口；正式 due 仍以思源内核为准 |
| 内容理解 | 上下文、章节、词条/词形/词义、例句、来源引用、术语解释、知识关系、材料版本和个人备注 |
| 管理与分析 | 搜索、筛选、批量操作、坏卡、旗标、掌握/覆盖视图、保持率、时间、练习结果、目标缺口、数据健康和导出 |
| 互通与生态 | Anki、内核 V2、拾遗、打卡、考试、复盘、雷切、人脉/资料捕获、事件、能力探测、分享包和本地补丁 |
| 平台体验 | 桌面、移动、窄屏、触控、键盘、读屏、主题、国际化、离线、同步、冲突、恢复、低带宽和大库 |

AI 不是单独的“AI 制卡模块”，而是覆盖上述能力域的智能协作层：材料筛选、来源核验、概念解释、卡型选择、题面生成、提示、应用任务、内容维护、学习报告、系列编排和思源 Agent 都应复用同一套上下文、权限、提示词、证据和降级契约。AI 输出属于 `derived/proposal`（派生候选），不能冒充内核事实、内容事实、正式评分或 due。

## 3. 能做与后置的关系

所有能力都可以进入长期目标，但按证据和依赖分阶段推进：

| 阶段 | 含义 | 进入条件 |
|---|---|---|
| **现在可做** | 依赖思源现有 API、当前数据模型和本地能力即可交付 | 有明确数据所有权、用户流程和验收 fixture |
| **近期可做** | 需要 V2、稳定事件或小规模交互研究，但技术路径清楚 | 宿主契约稳定，先完成降级和迁移设计 |
| **实验验证** | 需要真实用户、媒体、AI 或复杂题型验证价值 | 先做低保真/旁路练习，不改变正式调度 |
| **后置纳入** | 云同步、市场、多人协作、完整增量阅读、复杂媒体处理等依赖外部服务或大量基础设施 | 本地核心完成、隐私/成本/版权/恢复方案成立后再做 |
| **不应绕过** | 任何会破坏内核调度、隐私同意、数据可恢复性或能力真实性的做法 | 永久作为设计底线，而不是为了赶进度放弃 |

因此，“做不到先往后放”不等于删掉目标。后置能力必须进入能力矩阵，写清依赖、阻断条件、用户价值、最小验证和未来入口；没有条件时显示为“后置/N/A”，不能伪装成已支持。

## 4. 永久底线

1. **内核是正式调度事实源**：小驴可以做影子预测、练习、计划和可视化，但不偷偷建立第二套 FSRS 或覆盖内核 due。
2. **数据身份先于功能数量**：卡、来源块、词义、出现位置、字段、模板、媒体、版本、个人修改和外部事件必须能区分；没有稳定身份就不能自动合并。
3. **本地优先且逐次同意**：原文、卡面、联系人、媒体和 AI 请求各有边界；外发、联动、分享和云能力不得默认为开启。
4. **可降级、可恢复、可解释**：内核版本、设备能力、网络、插件缺失、同步冲突和导入失败都要有用户可执行的下一步。
5. **全面不等于虚假承诺**：竞品营销语、单个用户案例和一次实验不能直接变成学习效果声明；所有宣传必须对应发布包和验证证据。
6. **模块化吸收而非大杂烩**：题型、语言、课程、媒体、生态、AI 和云能力按模块/能力包加载，核心复习在最小环境中仍可用。

## 5. 产品架构的战略变化

现有 L0-L4 分层继续保留，并增加贯穿各层的 AI 编排平面：

```text
L5 未来能力层   云同步/市场/多人协作/完整增量阅读（后置，不能阻塞本地产品）
L4 生态协同层   拾遗·打卡·考试·复盘·雷切·Anki·外部捕获·事件协议
L3 学习体验层   复习·练习·课程·考试·语言·阅读·AI·统计·管理·分享
L2 内容领域层   卡型·字段·模板·来源·版本·媒体·词汇·知识关系·目标
L1 Gateway 层   FlashcardGateway、HostAdapter、CapabilityRegistry、TypedStore
L0 事实源层     思源内核 riff/V2、FSRS、文档/块、用户本地数据

AI 平面          TaskRegistry、ContextPack、PromptRegistry、ProviderRouter、SchemaValidator、EvidenceStore、AuditSink、Agent Bridge
```

新增的 `CapabilityRegistry` 不是让插件假装支持所有功能，而是让每个能力明确记录：版本、依赖、读写范围、是否改变内核状态、是否需要网络/AI/外部插件、失败降级和销毁责任。

### 5.1 AI 是贯穿各层的受控能力

AI 不只是 M2 的制卡按钮，而是学习对象全生命周期的辅助层：

| 生命周期 / 模式 | AI 可以帮助 | 必须保留的人类判断与事实边界 |
|---|---|---|
| 捕获、澄清 | 摘要、术语识别、问题拆解、前置概念建议 | 来源选择、版权/隐私范围、事实是否充分 |
| 建卡、创作 | 原子卡候选、题型变体、语言/代码/公式格式化 | 接受、修改、拒绝、答案是否准确和可复习 |
| 练习、复习 | 提示、解释、反例、追问、应用题候选 | 正式评分、due、revlog 和学习结果声明 |
| 应用、迁移 | 案例、变式、项目任务、复盘问题 | 用户的真实产出和专业判断，不把相似度当能力 |
| 维护、治理 | 过时检测、重复聚类、来源冲突和修订建议 | 删除/合并/分享、许可、隐私和版本发布 |

所有 AI 输出都要带任务、来源、模板、模型和同意范围的 provenance。AI 不能静默外发材料，不能直接写入正式调度，也不能以置信度、相似度或生成成功代替事实证据。优先接入思源内置 Agent，但必须按宿主版本协商 schema、工具权限、取消和流式能力；不具备能力时退回本地模板、手工流程或用户已授权的模型。

内置提示词按任务注册，而不是散落在组件中。每个模板包含输入字段、上下文预算、输出 schema、引用要求、拒答条件、语言/无障碍要求和版本号。模型或模板升级先经过脱敏黄金样本、注入攻击、隐私泄露、成本、延迟和学习结果相关性评测；通过后才允许成为默认版本，历史批次保持可比较和可恢复。

AI 的运行治理由四条账本组成：用户可理解的同意与外发记录、模型/提示词/来源 provenance、脱敏的请求成本与质量指标、失败和降级记录。账本不保存卡面原文、密钥或联系人敏感字段，用户可导出、删除和撤回。每个任务都有 token/费用/并发上限和降级阶梯，达到上限或遇到隐私/风险阻断时保留草稿和手工路径，不切换到未授权端点。

AI 平面还必须统一记录模板版本、模型/provider、输入范围哈希、来源引用、用户确认、成本、错误和恢复状态。用户或思源 Agent 发起的请求都经过“权限预检→范围预览→上下文组装→版本化提示词→结构化校验→候选/建议→人工确认→事实写入”流程；没有思源 Agent API 或模型时隐藏假入口，手工路径和核心复习仍可用。详见 [docs/29-AI战略与内置提示词体系](./29-AI战略与内置提示词体系.md)。

## 6. 成功标准

长期成功不能只用“功能数量”衡量，应同时满足：

- 用户能从任意材料进入一条清楚的学习路径，并能回到来源；
- 任何练习结果都能说明是正式内核复习、旁路练习、课程任务还是个人反思；
- 内容更新、分享、导入、删除、同步和恢复不会静默破坏个人学习历史；
- 复杂能力后置时，核心制卡、复习、统计和导出仍然独立可用；
- 用户研究能证明流程减少了真实阻断，而不是只证明用户喜欢截图；
- AI 只在有授权、可追溯、可评测和可降级的边界内参与；AI 质量、成本和学习结果分别衡量，不用单一指标包装成效果证明；
- 市场页面写的是当前可验证能力，路线图写的是可追踪的远期目标。
- AI 生成候选、AI 辅助解释、人工确认和正式内核复习的边界在界面、日志、统计和宣传中始终可区分。

## 7. 本次战略调整的执行动作

1. 把设计总纲的定位从“V2 之上的体验层”升级为“思源的全域学习操作系统”；V2 仍是正式调度和数据事实源。
2. 把“明确不做”改成“后置纳入/永久底线”两类，避免过早放弃云、市场、增量阅读等远期能力，也避免为实现它们绕过基础约束。
3. 在路线图中增加全功能矩阵、阶段门槛和后置能力登记；版本只承诺当前阶段已验证的子集。
4. 在待办中增加总目标治理项，持续维护能力矩阵、依赖登记、状态事实源、跨模块验收和远期能力入口。
5. 在 README、市场报告、上手指南、隐私说明、发布说明和宣传素材中统一使用本战略，消除“已实现/实验中/规划中/后置”的混用。

> 本战略不会要求一次开发完所有模块。它要求每一次开发都朝完整能力矩阵推进，并且把暂时做不到的能力留下可验证、可恢复、可继续的路径。
