# 2026-10-18 分享包导入完整性与异常回归

本轮从 `3c5a61f` 继续，版本保持 v0.210.4；本轮代码为本地未发布修复，未推送、未创建 Release。目标是修复已有 `.lvcards` 导入的读取、去重、确认和写入结果语义，不将离线测试视为真实思源导入验收。

## 问题与修复

1. **大库读取不完整、正文来源不正确**：旧路径只读第 1 页 500 项，并用 `getRiffCards.content` 作 Markdown 指纹。新纯模块 `src/core/lvcards-import.ts` 顺序读取全部页，核对页数、总数和唯一 ID；然后每 400 个 ID 查询原始 `blocks.markdown`，显式 `LIMIT` 避开宿主默认 SQL 行数限制。分页漂移、空页、缺失/重复身份、SQL 返回缺行或无正文均停止导入，不将不完整结果当空库。
2. **包内重复和身份冲突**：预览对包内正文去重，保留同 ID 不同正文的冲突并阻止整包写入；不再把冲突误报为“全部重复”。缺失/空白 ID 生成同一文件内稳定且避开显式 ID 的占位身份；未知格式对象不会因字符串强制转换抛异常。缺失 ID 不保证跨文件重排后的身份稳定。
3. **空白语义和损坏条目**：指纹只归一化 CRLF/CR 与首尾空白，保留代码缩进、内联空格和 Markdown 硬换行。有效与损坏条目混合时整包解析失败并指出条目位置，避免静默丢卡后报告部分“成功”。写入前复用 `validateCardEntry`，缺题面、答案标记或结构无效的卡片不会创建导入文档；结构通过仍不代表知识事实正确。
4. **确认框文本注入**：分享包卡组名称及 Obsidian 文件名产生的摘要统一转义后进入 HTML；分享包模板单次替换，卡组名中的 `${n}` 保持字面文本。
5. **创建后块对位**：只查询新文档的一级块，显式读取 `root_id`、`parent_id`、类型和原始正文，使用 `LIMIT 卡片数 + 1` 检测多余块。核对数量、唯一非空 ID、根/父身份和严格正文，按内容一一消费匹配，不依赖 SQL 顺序。合法单块代码/列表可以入组；多段正文被宿主拆分或合并而无法一一对位时停止整批入组，保留文档并显示文档 ID。
6. **不伪报写入成功**：笔记本、文档或卡组返回空 ID 时停止后续写入。`addRiffCards` 返回后再次完整读取目标卡组，逐个确认新块身份；缺失或回读失败显示待核对，不自动重放写入。创建文档结果未知、已保留文档、入组结果未知分别说明，用户先核对再重试，不自动删除可能已写入的文档。

## 宿主契约与验收边界

契约核查依据包括本地思源源码 `kernel/model/flashcard.go`、`search.go` 及官方源码 `kernel/api/sql.go`、`kernel/sql/query_limit.go`；官方查询时 master 为 `7a7430d8a3cf362e23de004a454ddabe651dc778`。源码显示搜索内容及 SearchBlock Markdown 可被截断，默认 SQL 搜索限制与显式 LIMIT 不同，入组回执也不足以证明逐块持久化。这是实现依据，不是本轮真实宿主运行证据。

本轮未重跑 Chrome 夹具、隔离内核、真实思源、Android、读屏或真实文件系统导入。前轮浏览器截图只对应前轮构建；本轮成功/失败路径由真实 Settings 组件和受控 API 替身验证。真实索引延迟、多窗口同时编辑、持久化失败与宿主 Markdown 规范化仍须按 docs/34 验收；发生无法确认的状态时当前实现保守停止，不承诺分布式原子性或自动回滚。分享包中的 memo、tags、fsrsParams 等可选元数据没有在本轮新增落地，不将其描述为完整恢复。

本轮未新增源卡 ID 到导入块 ID 的持久化台账；相同正文重导可按指纹跳过，但外部分享包正文修改后，不保证能与先前导入的新块识别为同一来源更新。现有冲突检查只对当前可对齐的相同 ID 生效，不自动覆盖已有卡片。
