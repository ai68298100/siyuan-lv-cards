# 2026-10-19 思源通用 API 契约与大库韧性测试闭环

本轮从 `3c5a61f` 继续，版本保持 v0.210.4；本轮代码为本地未发布修复，未推送、未创建 Release。目标是补齐 `src/api/siyuan.ts` 中核心底层数据契约的自动化测试覆盖，消除此前工程风险表中关于“大库文档归属查询并发承载与分块契约缺乏离线验证”的 P1 风险，并闭环本地媒体资源三态探测逻辑。

## 问题与修复

1. **大库文档归属与标题查询契约验证缺失**：此前 `getBlockDocMap`（按 400 ID 切片、最大 3 路并发查询 `id, root_id, box`）和 `getDocTitles`（分块查询根块 content 并取首行作为文档标题）支撑着学习仪表盘的文档维度覆盖率（AQ-12），但缺乏专项单测对超过 400 项的大卡组切片、并发有界调度、SQL 单引号注入防御、以及查不到块时的优雅缺失行为进行离线保障。
2. **本地媒体资源三态探测边界验证缺失**：`probeAssetRefs` 是维护中心媒体健康检查（BI-20）的核心接口。由于思源底层 `statAsset` 使用 `code=1` 表示本地文件缺失，且仅对以 `assets/` 开头的本地路径有效，该接口通过三态映射（`present` / `missing` / `unknown`）与并发控制防止外部网络图片或文档级相对路径被误标为“缺失/损坏”。该边界此前缺乏离线自动化回归。
3. **构建测试套件 `tests/siyuan-api.spec.ts`**：
   - **大库切片与并发契约**：使用 850 个块 ID 验证严格切分为 400 + 400 + 50 共 3 批，并限制并发度不超过 3；
   - **SQL 防注入与单引号转义**：验证含有特殊单引号的 ID（如 `block'with''quotes`）被严格转义为 `''`，杜绝 SQL 语法报错与注入；
   - **根块首行标题截取**：验证对于包含多行正文的根块，准确截取第一行并执行 `trim`；
   - **媒体探测三态判定**：验证 `assets/` 存在的图片判定为 `present`、`code=1` 判定为 `missing`、外链/非 assets 路径及超时报错判定为 `unknown`，且重复路径自动去重，输出有序；
   - **系统版本自诊断容错**：验证 `kernelVersion` 正常获取与异常降级 `"?"`。
