# 小驴闪卡 · 当前状态评审与精品化待办

> 评审日期：2026-10-05  
> 代码基线：`v0.185.0`，`main b133a7e`  
> 定位：本文件是 `docs/17`、`docs/30`、`docs/31`、`docs/34`、`docs/36` 的执行补充。它负责把当前事实、发布判断和下一阶段可执行任务收拢到一处，不替代历史条目和工作包索引。

## 1. 先给结论

小驴闪卡已经越过“插件骨架”阶段，形成了较完整的本地优先闪卡平台：入口、卡片创建、内核调度、复习、统计、管理、学习目标、材料收件箱、维护队列、考试计划和 AI 制卡安全链都已有代码、测试和文档支撑。当前最重要的工作不是继续堆叠长尾功能，而是把已经存在的能力变成用户可以稳定依赖的产品。

当前可以对外描述为：**离线工程和 GitHub 发布链路已具备，核心功能代码已具备，真实设备和真实模型验收仍未闭环，集市发布条件尚未满足。**

产品进入下一阶段前，必须完成三件事：

1. 在真实思源桌面端和 Android 真机完成 `docs/34` 的 E2E-3 `W-1~W-12`，逐项留下版本、设备、步骤和截图/录屏证据；
2. 修掉核心旅程中的可靠性和交互阻断，包括手势评分、卸载清理、异步确认、持久化串行化、内核请求超时和管理器批量语义；
3. 让 README、用户指南、隐私说明、发布包和产品素材只宣传已验证的能力，并把实验中、宿主依赖和规划中能力明确标出来。

### 2.2 已经形成的产品能力

- **核心数据边界清楚**：正式 due、评分和 FSRS 调度以思源内核为事实源；插件维护本地日志、会话现场、目标、收件箱、维护和 AI 作业等辅助数据。
- **核心学习链条已具备**：材料入口 → 卡片创建 → 复习评分 → 本地统计 → 管理维护；学习目标、收工原因、返场检查、时间预算和减负选择已经补上旅程语义。
- **输入和练习方式较丰富**：快速问答、挖空、标记扫描、打字对照、TTS、选择题、配对、图片遮挡、混合题型轮换。
- **AI 已有安全底座**：前置资格检查、材料围栏、注入隔离、上下文预算、作业断点、紧急停用和撤销同意均已有纯模块或接线。
- **工程组织较成熟**：按 chunk 懒加载，存在 UI Kit、纯逻辑模块、存储体检、诊断、事件契约和治理脚本。

### 2.3 仍不能当作完成的能力

- 代码存在不等于桌面、Android、iOS、浏览器和第三方主题都能用；`frontends`/`kernels` 声明是兼容目标，不是验收结果。
- 纯模块通过不等于 UI 状态、焦点、软键盘、手势、后台恢复和错误路径正确。
- AI 请求成功不等于拒绝外发、取消、401/5xx 降级、敏感来源、预算、旧响应覆盖和中断续传都正确。
- 原型、README 和路线图描述的是目标体验，必须带状态标签后才能成为用户承诺。

## 5. P1：未来 2~4 个开发批次

### P1-A 把主流程做成“下一步明确”的产品

- **今日工作台**：中心首屏先显示“继续上次现场、今天建议、可用时间、下一动作”，统计和深度指标渐进展开；无到期卡时给出制卡/维护/回源建议。
- **学习现场恢复**：入口上下文、筛选、卡组范围、页码、滚动、焦点和中断原因在重载/返回后恢复；恢复失败时显示现场快照和重新开始选项。
- **管理器全库语义**：明确“当前页 / 当前筛选结果 / 全部匹配结果”三种范围；显示总数、选中数和预计影响；跨页选择、部分成功、失败重试和撤销要逐项反馈。
- **来源到卡面审核**：详情中同时显示来源块、字段、实际题面、答案、历史版本和回源按钮；内容更新时给出影响卡片清单，避免只改原文而不知卡片已失真。
- **统一状态设计**：所有页面使用 loading、empty、stale、error、unknown、partial-success 六类状态；每类只播报一次，文案必须带下一步。

### P1-B 移动、无障碍和主题

- `LvDrawer` 增加焦点移入、Tab 循环、焦点归还、`aria-labelledby`/`describedby` 和异步关闭保护；统一 Dialog/Drawer 的 Esc、遮罩、X 和取消语义。
- `LvTabs` 补齐 `tablist`、`tabpanel`、`aria-controls`；`LvSegmented` 实现完整 roving tabindex/radiogroup；复杂 `LvRow` 拆成清晰的 label、状态和操作区域。
- 把可点击 `div` 改为 button 或提供键盘等价；补齐图标按钮标签、焦点可见样式、live region、错误关联和读屏顺序。
- 逐页验收 320px、150% 字号、软键盘、横竖屏、safe-area、低对比主题、第三方主题和高对比模式；覆盖 review、manager、settings、pairing、challenge、onboarding、目标、收件箱和维护。
- 收敛业务页面 inline style 到 Starline token；为深色、浅色和宿主主题建立视觉回归截图，避免同一组件在不同页出现不同语义。

### P1-C AI 产品化

- **材料审阅**：请求前显示可编辑原文、来源块、追加/替换/删除片段、token 估计和外发范围；每个来源可单独禁止外发。
- **候选状态**：严格区分待审、已编辑、已接受、已拒绝、已落卡；默认不把“生成”当作“采用”。
- **逐卡改写**：单卡重生成携带当前卡、修改意图、来源证据和目标字段；失败只影响该卡，不覆盖其他候选。
- **质量和证据**：展示 schema、来源覆盖、原子性、泄漏、重复、难度和模型配置快照；质量分是审阅提示，不冒充掌握度。
- **同意与成本中心**：按 provider/model/task/template 显示权限、最近调用、估算/实际成本、撤销入口和清理待发作业。
- **无 AI 等价路径**：每个 AI 入口都给出手工、规则或本地替代，并说明损失和不可替代部分。

### P1-D 数据、诊断和发布工程

- 管理器、复习和导入导出增加备份前预览、恢复演练、版本迁移和冲突报告；先支持当前私有数据，再扩展跨设备。
- 增加用户可见的操作审计日志：时间、对象、动作、结果、来源、失败原因和撤销入口；绝不记录材料明文、密钥或完整 prompt。
- 将 chunk-loader 的网络错误改为可控 mock，测试输出只保留真正失败；新增发布包内容清单、SHA-256、可选 SBOM 和安装 smoke。
- Release workflow 与 CI 复用完整门禁：`check`、`test`、i18n、governance、gzip、包内容和版本一致性；避免重复 zip 产生陈旧产物。
- `scripts/deploy-device.mjs` 不提交硬编码本机路径；改为 CLI 参数/环境变量并做路径存在性检查，或仅作为本地忽略脚本保存。（已完成于 v0.185.1：`LV_DEVICE_PLUGIN_DIR` 环境变量 + dist 完整性检查）

### P1-E README、GitHub 和支持体系

- README 首屏在 30 秒内回答：解决什么问题、如何安装、第一张卡怎么做、哪些能力已验证、AI 数据发往哪里。
- 中英文 README 使用同一能力矩阵、同一版本和同一兼容性口径；修正英文 badge 相对链接，全部使用仓库绝对 URL。（badge 链接已完成于 v0.185.1 文档批次）
- 增加“已验证环境”表：思源版本、桌面/Android/iOS/浏览器、主题、已通过路径、已知限制和最后验证日期。
- 增加截图/GIF 索引、隐私快速入口、故障排查、诊断脱敏说明、迁移/备份说明和集市状态；把原型明确标为目标设计。

## 6. P2：主链稳定后的能力扩展

这些项目有价值，但不应在 P0/P1 证据闭环前抢占核心资源：

1. **Anki 与学习包互通**：`.apkg` 两阶段导入、字段/媒体/历史映射、重复检测、损失报告、幂等导出和版本升级。
2. **备份与恢复中心**：可读 manifest、增量备份、恢复到新工作区、误删回滚、升级前快照和恢复演练。
3. **语言学习**：词条/词义/例句/出现位置、原音、听写、跟读、拼写和媒体缺失降级。
4. **课程与考试**：考纲、章节、先修依赖、投入预演、动态复习建议和教师蓝图；所有建议都标明数据口径。
5. **理解与应用**：解释、辨析、案例、开放回答、迁移练习和真实产出证据；不把选择题正确率当作掌握证明。
6. **研究工作台**：外部来源适配器、断言—证据对象、冲突并列、引用回链；外部检索必须单独授权。
7. **系列插件联动**：拾遗、考试错题、打卡、专注和复盘通过版本化事件协议连接；缺少兄弟插件时保留本地路径。
8. **Agent/批量操作**：先只读探测，再给出计划、影响、确认、执行和审计；写入操作必须复用现有事务和撤销边界。

## 7. P3：长期探索和立项条件

云同步、多人协作、内容市场、独立客户端、小组件、商业化和完整增量阅读属于长期平台项目。进入建设前必须先完成用户研究、成本/隐私评估、退出方案、数据可迁移性和本地替代路径；没有这些条件时只保留研究，不提前制造账号、服务端和迁移负担。

## 8. 建议开发顺序

1. **证据清点**：执行 `W-1`，确认 chunk 部署和真实首开；同步建立设备、宿主、主题和证据目录。若 W-1 失败，先修资源加载和部署脚本。
2. **核心阻断修复**：按 `P0-B1 → P0-B2 → P0-B3 → P0-B4 → P0-B5 → P0-B6` 修复复习、生命周期、事务、持久化和超时；每项先测试，再做最小真机复验。
3. **完成 E2E-3 和发布事实**：执行 `W-2/W-3/W-8/W-9`、`W-4/W-6/W-7`、`W-5`、`W-10~W-12`；同时完成能力状态矩阵、README/指南/隐私同步和真实素材采集。
4. **P1 主流程和质量**：优先今日工作台、管理器范围、来源审核、Dialog/Drawer 焦点、320px 移动适配、AI 材料预览与同意中心，再做审计日志、备份恢复和发布自动化。
5. **扩展能力**：仅在核心旅程的设备验收通过、崩溃/数据损坏风险受控、发布文档稳定后，按 P2 的用户价值和宿主依赖逐个立项。
