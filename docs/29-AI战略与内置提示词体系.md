# 小驴闪卡 · AI 战略与内置提示词体系

> 版本：AI 产品基线 v1.2（2026-10-02）
>
> 本文把 AI 从“制卡按钮”提升为贯穿小驴闪卡全生命周期的能力层。它只记录产品规划、宿主契约、提示词模板和验收边界，本轮不授权开发。当前已实现能力仍以待办清单、版本说明和真机证据为准。
> 排期事实源为 [30-待办治理与执行顺序](./30-待办治理与执行顺序.md) v1.2，历史条目的规范工作包主归属见 [31-待办工作包索引](./31-待办工作包索引.json)。用户可见的页面与交互依据 [32-产品体验优化与页面蓝图](./32-产品体验优化与页面蓝图.md)。本文的模板目录是能力范围，不是必须同时完成的开发批次。

## 1. AI 在产品中的位置

小驴闪卡不是把 AI 接到某个输入框上，而是让 AI 帮用户完成**发现、理解、组织、练习、应用和维护知识时的高认知负担工作**。AI 的输出始终是可追溯、可编辑、可拒绝的候选；学习事实、正式评分和内核调度仍归用户与思源内核所有。

AI 应覆盖两条互补路径：

```text
用户 → 小驴界面 → AI 工作流 → 候选/解释/建议 → 用户确认 → 学习对象与内容事实
思源 Agent → 能力注册表 → 小驴只读查询/准备动作 → 预览 → 用户确认 → 小驴写入
```

第一条路径面向用户主动操作，第二条路径让思源内置智能体理解小驴的学习对象、目标、会话和结果。两条路径必须共享同一套能力声明、权限范围、提示词模板、输出 schema 和审计记录，不能各自发明一套事实源。

AI 的最终价值不是“生成更多卡”，而是帮助用户达到六类结果：

| 结果 | AI 可承担的工作 | 必须由谁确认 |
|---|---|---|
| 记得住 | 发现遗忘原因、改进题面、提出提示阶梯、准备旁路练习 | 用户评分与内核调度 |
| 用得上 | 生成案例、反例、变式、步骤 rubric 和迁移问题 | 用户答案与应用证据 |
| 找得到 | 来源定位、引用闭包、术语解释、关系与前置建议 | 用户接受事实与来源 |
| 改得动 | 差异摘要、重复检测、模板迁移、内容维护建议 | 用户确认写入/合并 |
| 负担得起 | 按时间、目标、精力生成取舍建议和收工摘要 | 用户选择范围与计划 |
| 带得走 | 导出映射、能力损失报告、迁移修复建议 | 用户确认导出与外发 |

## 2. AI 能力分层

AI 不是独立的第十三个模块，而是横跨所有模块的能力平面：

| 层 | AI 职责 | 事实边界 |
|---|---|---|
| 捕获层 | 来源分类、去重、OCR/转写候选、问题提取、许可提醒 | 不自动建卡、不把来源猜测当事实 |
| 理解层 | 摘要、概念解释、例子/反例、术语和前置关系 | 必须带来源片段；材料不足显示未知 |
| 创作层 | 各卡型候选、字段填充、变体、提示、难度和答案规则 | 先预览，结构校验通过后才可写入 |
| 练习层 | 提问、提示阶梯、对比/变式、语言听写、应用任务 | 旁路记录与正式 rating 分离 |
| 反馈层 | 错误原因候选、误解簇、学习结果叙事、收工摘要 | 不能自动诊断能力或改 due |
| 维护层 | 重复/泄漏/失效检测、版本差异、来源健康、迁移损失 | 修改、合并、删除必须预览和可撤销 |
| 编排层 | 目标、课程、考试、系列插件任务排序和下一步建议 | 只给建议；不替其他模块拥有事实 |
| Agent 层 | 通过思源 Agent 查询和准备小驴动作 | 写入型工具默认需确认，最小权限 |

## 3. 思源 Agent 接入原则

思源已有前端 `Plugin.addAgentCapability` 和 Kernel `siyuan.agent.registerCapability` 两种智能体能力入口。2026-10-02 核对了 Petal main（`32afa1b`）的公开类型声明；具体行为、可用宿主版本和权限仍需真机验证。

| 宿主入口 | 已核对的声明 | 小驴适配方式 |
|---|---|---|
| [前端 addAgentCapability](https://github.com/siyuan-note/petal/blob/32afa1b6631d5a649456365fa5ca525c39c78a67/siyuan.d.ts#L887) | description、inputSchema、outputSchema、effects、actionEffects、handler；返回 capability 标识 | 承接当前编辑器、选区、卡片和确认界面；UI 状态由前端持有 |
| [Kernel registerCapability](https://github.com/siyuan-note/petal/blob/32afa1b6631d5a649456365fa5ca525c39c78a67/kernel.d.ts#L599) | register/unregister、config、handler、稳定 ID 和命名空间工具名 | 只有需要长期任务、多 client 或服务状态所有权时才使用 Kernel Plugin |
| [effects 声明](https://github.com/siyuan-note/petal/blob/32afa1b6631d5a649456365fa5ca525c39c78a67/kernel.d.ts#L629) | localRead、localWrite、dataEgress、externalCost | 小驴额外维护 kernelMutation、crossPlugin 等内部策略；不能把自定义字段冒充宿主接口 |

这两种入口是让 Agent 调用小驴工具的机制，不能据此推断插件可以直接启动一个 Agent 对话或继承其全部权限。对话打开、流式生成、取消、可复用系统提示词等接口需要分别探测；不可用时使用现有 AI 调用或手工入口。类型声明不证明运行时的权限强制、取消或自动确认已经实现。

Agent 宿主探测与统一 AI 调用、模板和 schema 设计可以并行。只读 handler 也必须等待实际权限检查、输入/输出 schema、外发边界和脱敏审计入口成立，才可按能力注册；之后再增加确认型计划工具。Agent 不可用时，普通 AI 工作流和手工路径仍可按自己的门禁交付，不等待宿主完整 Agent 能力。

### 3.1 能力注册

每项 Agent 能力登记：`id`、用途、输入 schema、输出 schema、读写对象、网络/模型依赖、是否读取原文、是否改变内核状态、确认级别、撤销方式、失败降级和版本。

首批规划能力：

| 能力 ID | 默认级别 | 用途 |
|---|---|---|
| `lv-cards.today-snapshot` | 只读 | 返回今日到期、目标、积压和设备限制摘要 |
| `lv-cards.find-learning-objects` | 只读 | 按目标、来源、状态、能力类型检索学习对象 |
| `lv-cards.explain-object` | 只读/需来源 | 基于用户选择的来源解释概念，返回引用和未知项 |
| `lv-cards.prepare-candidates` | 预览后确认 | 从用户选择材料生成候选卡/候选问题 |
| `lv-cards.prepare-review-session` | 预览后确认 | 按时间预算准备复习、练习或应用会话，不评分 |
| `lv-cards.review-summary` | 只读 | 汇总正式复习、旁路练习、应用证据和未决问题 |
| `lv-cards.find-maintenance-debt` | 只读 | 找出重复、泄漏、过时、无来源和待审核对象 |
| `lv-cards.export-learning-report` | 预览后确认 | 生成脱敏 Markdown/JSON 报告和损失说明 |

Agent 不应默认拥有“直接评分、改 due、删除来源、外发原文、批量覆盖字段”等能力。需要写入时，Agent 只能生成计划和差异，由小驴界面展示确认；确认后的写入仍经过既有 Gateway、TypedStore、事件和审计链。

### 3.2 Agent 与模型调用的边界

- 思源 Agent 负责理解用户意图、选择已授权工具和串联步骤；小驴负责工具真实权限、数据身份、schema 校验和事实写入。
- 小驴内置 AI 工作流可使用思源 AI 配置或用户明确配置的 OpenAI 兼容端点；端点、模型、区域、费用和数据保留期必须在调用前可见。
- Agent 读取卡面、来源和联系人前必须获得范围授权；“今日摘要”优先返回计数和状态，只有用户展开才读取原文。
- Agent 失败、未安装、旧协议、无模型、无网络或被拒绝时，核心制卡/复习/导出仍有手工路径。

### 3.3 内置模板如何供思源智能体使用

提示词分为三种用途：模型任务模板负责生成卡片/解释/练习；Agent 工具描述负责告诉智能体何时选择小驴能力、需要什么参数以及会产生什么效果；多步骤学习配方负责组织“澄清目标→选择材料→生成候选→审阅→创建→复习”的过程。工具描述必须写清输入不足如何追问、确认点、材料范围和示例，不能只写“调用闪卡功能”。

规划中，用户可从模板目录把学习配方复制或导出给思源 Agent；宿主若开放正式技能/提示词注册接口，再进行版本化安装和更新。公开 `addAgentCapability/registerCapability` 只证明工具注册存在，不证明可以自动注入系统提示词、打开 Agent 会话或写入某个私有 skills 目录。无正式接口时提供可复制的配方和小驴任务界面，不能依赖私有文件路径或 DOM。

首批 Agent 配方示例：

- **“用这份讲义准备考试”**：确认考试目标和日期→预览讲义范围→提取概念与缺口→按卡型生成候选→用户审阅→创建卡→打开课程/考试计划预览。
- **“这张卡我总忘”**：读取用户选择卡片及允许的错因摘要→追问是理解、题面还是回忆问题→列出拆分/换题型/加例子的方案→用户选择→预览修改差异；不重置历史。
- **“今天只有十分钟”**：查询脱敏今日摘要→比较正式复习、应用和维护范围→用户选择→打开相应会话；模型不自行重排 due。

Agent 工具“本地读取”不保证结果留在本机：结果进入宿主模型对话可能产生外发。因此卡面、来源片段、个人答案和联系人信息在工具返回之前也要检查范围与模型端点，默认只返回计数、引用和必要摘要。

## 4. 内置提示词模板标准

提示词不是散落在 UI 中的字符串，而是版本化的产品资产。每个模板必须包含：

```text
templateId / version / locale / task
systemRules                # 角色、边界、不得做的事
inputSchema / contextPolicy # 允许的字段、来源范围、脱敏策略
outputSchema               # JSON/Markdown 结构与必填字段
groundingRules             # 引用、证据、未知和冲突处理
qualityChecks              # 原子性、重复、泄漏、长度、语言和安全
confirmationLevel          # readonly / preview / confirm
fallback                   # 无模型、超时、解析失败、材料不足
evaluationFixtures         # 回归样本、评分维度和已知反例
```

### 4.1 通用系统约束

以下约束应作为所有模板的共同前缀，由模板注册器注入，而不是依赖用户自行粘贴：

```text
你是小驴闪卡的学习辅助，不是最终事实裁判。
只使用 INPUT 中明确提供且允许使用的材料；材料不足时输出 UNKNOWN，并说明缺口。
不要捏造来源、引文、评分、掌握度、due、学习效果或用户意图。
把事实、推断、建议和待确认项分开；每个事实必须附可校验的 sourceId/occurrenceId；无法引用时列为 UNKNOWN/待核实，不作为事实输出。
输出必须符合指定 schema；不能用额外自然语言替代必填字段。
不要直接修改卡片、评分、due、复习历史或来源；这些动作只能生成候选和差异。
```

| `agent.action-ledger.v1` | Agent 多轮行动账本 | 显示每次读取、拟写、待确认、失败和撤销点，支持中断恢复 |
| `share.redaction-audit.v1` | 分享前脱敏审计 | 列出原文、个人答案、私密标签、联系人和未授权媒体的可移除项 |
| `memory.selective.v1` | 选择性记忆 | 用户勾选目标、偏好和术语是否进入会话记忆，按学习包隔离且可忘记 |
| `manual.fallback-parity.v1` | 无 AI 等价路径 | 为每个 AI 入口返回手工查来源、制卡、rubric 或复习路径 |

### 4.2.1 模板与逐模块任务映射

BV 任务复用上述通用模板，并在需要时注册专用变体；专用变体不能绕过统一的权限、证据、schema 和人工确认链。

| BV 任务 | 基础模板/专用变体 | 重点验收 |
|---|---|---|
| BV-1—BV-3 材料价值、目标澄清、来源冲突 | `capture.classify`、`research.claim-evidence`、`intent.route` | 引用、未知项、目标由用户确认 |
| BV-4—BV-12 卡型路由、原子拆解、挖空、干扰项、rubric、列表/代码/图片/OCR | `card.atomic-qa`、`card.cloze`、`card.choice`、`card.application` + `card.type-*` 变体 | 能力映射、反泄漏、坐标/时间戳和不可核验标记 |
| BV-13—BV-14 词义、阅读与字幕 | `language.sentence-mining`、`explain.grounded` + `language.reading-guide` | 词义/读音/拼写分离，揭示顺序可跳过 |
| BV-15—BV-18 复习教练、错因、应用情境、产出反馈 | `review.tutor`、`review.error-diagnosis`、`teachback.evaluate`、`artifact.iterate` | 不代评分，按 rubric 给最小下一步和 diff |
| BV-19—BV-20 leech 与来源更新 | `maintain.quality-lint`、`maintain.diff-review`、`maintenance.impact-explain` | 受影响实例、个人字段保护、确认后写入 |
| BV-21—BV-22 课程考试、作者教师学习包 | `plan.session`、`agent.tool-plan` + `plan.course-blueprint`/`author.learning-pack` 变体 | 不创建第二调度器，许可和学习者历史隔离 |
| BV-23—BV-24 报告与系列 Today 编排 | `report.learning-outcome`、`agent.tool-plan` + `report.statistics-explain`/`series.today-orchestrate` 变体 | 数字可回溯、工具计划先确认、失败逐项补偿 |

### 4.2.2 制卡体验与模板的衔接

BX-2 定向局部改写是 `WP-card-authoring` 的产品交付；制卡负担预演深化已有 BA-11“新材料投入与范围预览”，主归属保持 `WP-goal-journey`，制卡界面引用它的估算与取舍契约。两者复用 BU 的统一调用、证据、schema、人工确认和候选治理，以及 BV 的任务质量验收，不建立新的 AI 平台，也不拆出 24 套任务服务；其他页面可以按自己的业务状态引用这些能力。

| 产品切片 | 复用任务与拟定变体 | 需要补齐的输入/输出边界 |
|---|---|---|
| BX-2 定向局部改写 | `card.atomic-qa`、`card.cloze`、`maintain.quality-lint` 的局部改写变体；BU-15、BV-5/6/19 | 输入当前对象/版本、知识点、限定来源、本次意图、人工锁字段；输出字段 diff、引用、无法确定项及拒绝原因，不改知识点、锁字段或学习历史 |
| BA-11 制卡负担预演验收深化 | `capture.classify`、`card.atomic-qa`、`intent.route` 的生成取舍变体；BV-1/4/5、BU-6/24 | 输入关键最少/数量上限/覆盖优先策略及本地估算；输出候选概念、取舍理由、覆盖缺口与未知，不能凑张数或自行预测 due |

### 4.3 五个核心模板的内置骨架

下面是拟定的模板骨架，供后续注册与 fixture 设计使用。实际实现时由 `ContextPack` 填入变量，并由 `SchemaValidator` 校验输出；用户可编辑任务参数，不能覆盖安全前缀和事实边界。

```text
[card.atomic-qa.v1]
角色：原子闪卡编辑器
任务：从 <source> 中只提取一个可独立回忆的事实、关系或步骤。
要求：问题只考一个动作；答案包含必要条件和例外；每个断言绑定 occurrenceId；无法从来源确认时返回 UNKNOWN。
禁止：把标题、标签、上下文直接泄漏到问题；拼接多个无关事实；补写来源没有的结论。
输出：{q, a, hint, explanation, sourceRefs[], difficulty, warnings[], requiresConfirmation:true}
```

```text
[explain.grounded.v1]
角色：基于来源的学习解释器
任务：为 <learnerLevel> 用户解释 <concept>，只使用授权的 sourceRefs。
顺序：一句话定义 → 直观例子 → 反例/边界 → 与前置概念关系 → 自测问题。
要求：事实、推断、类比分栏；每个事实带引用；冲突来源并列展示；材料不足明确 UNKNOWN。
输出：{definition, examples[], counterexamples[], prerequisites[], selfCheck[], evidence[], uncertainties[]}
```

```text
[review.tutor.v1]
角色：不替用户评分的复习教练
任务：根据 <goal>、<card> 和 <answer> 选择下一步最小帮助。
策略：先指出已命中的要点，再只给一级提示；用户请求或确认后才升级提示；始终允许跳过并自行评分。
禁止：直接宣布掌握、调用 reviewCard、改变 due、把模型相似度当正确率。
输出：{acknowledged[], nextQuestion, hintLevel, evidence[], uncertainty, suggestedAction, requiresConfirmation:false}
```

```text
[maintain.diff-review.v1]
角色：内容维护审阅员
任务：比较 <oldSourceVersion> 与 <newSourceVersion>，定位受影响的学习对象和应用任务。
分类：只改文字 / 事实变化 / 条件变化 / 来源失效 / 需要人工核验；个人字段和复习历史永远单独列出。
禁止：静默合并、删除历史、把来源变化当遗忘、直接改 due。
输出：{changes[], affectedObjects[], protectedFields[], proposedActions[], conflicts[], evidence[], requiresConfirmation:true}
```

```text
[agent.tool-plan.v1]
角色：小驴 Agent 计划器
任务：把用户请求转为最小权限的工具调用计划。
要求：先列意图、读取范围、预计输出和每个确认点。写入、外发和删除只能在明确确认后生成可审阅的计划；正式评分与 due 不属于 Agent 执行工具，只能返回建议并转到普通复习/改期界面由用户操作。工具失败时给手工替代。
输出：{intent, steps[{tool,scope,effect,requiresConfirmation}], proposedWrites[], risks[], fallback, auditLabel}
```

### 4.3.1 局部改写与生成取舍的拟定约束

局部改写先明确“修改哪一个对象、改善哪一点”。单卡重新生成不能只把整份材料再生成任意一张卡；局部建议也不能覆盖用户已确认的内容。输入不足、来源冲突或意图要求改变知识点时，应先澄清或转到新对象创作预览。

```text
[BX-2：局部改写变体草案，未注册/未验证]
输入：currentObject{id, version, conceptIds[], fields}、allowedSources[{sourceId, occurrenceId, version, snippet}]、intent{operation, goal}、lockedFields[]。
任务：按本次意图缩短问面、补充必要条件、调整例子或准备拆分候选，只使用限定来源，保留当前知识点及人工锁字段。
输出：{status, objectId, baseVersion, fieldDiffs[{field, before, after, reason, sourceRefs[]}], preservedFields[], uncertainties[], missingInputs[], refusalReasons[], requiresConfirmation:true}。
禁止：把“重写”变成另一知识点；改变锁字段；捏造来源；直接覆盖卡片、来源、评分、due 或历史；拆分时冒称已创建新卡。
核验：本地校验对象/版本、来源范围及锁字段；越界差异拒绝应用，版本变化重新预览。用户逐项接受、编辑或拒绝后，才由既有事务入口写入。
```

```text
[BA-11/BV-5：生成取舍变体草案，未注册/未验证]
输入：goal、allowedSources[]、strategy（关键最少/数量上限/覆盖优先）、maxCount（可选）、用户确认的时间预算、localLoadEstimate{observations, sampleSize, window, assumptions, ranges, unknowns}。
任务：为目标筛选值得制卡的知识点，解释选取与排除理由。关键最少只保留必要概念；数量上限可以少于上限；覆盖优先标出缺口和分批方案。
输出：{strategy, proposedConcepts[{conceptId, reason, sourceRefs[]}], candidates[], excludedConcepts[], coverageGaps[], loadExplanation{localEstimateRefs[], caveats[]}, uncertainties[], requiresConfirmation:true}。
禁止：为凑张数补写事实或重复卡；以卡量表示掌握；由模型编造耗时、复习次数、未来 due 或精确 FSRS 预测。
核验：数量、证据和覆盖范围由本地规则校验；负担数值只引用已观测数据与明示假设产生的本地估算，用户可修改假设或缩小范围。
```

负担预演分别展示审核、首练及可依据本地规则估算的后续投入，注明样本量、时间窗、卡型差异和不确定区间；新用户或缺乏适用数据时显示“未知”，可让用户填写用于试算的时间假设。估算不是正式调度，不生成未来到期事实；不能计算的后续负担保留未知，AI 仅解释现有数值、缺口和取舍。实际入库数量与正式 due 仍在用户确认后由业务写入及内核决定。

### 4.4 模板质量要求

生成数量不能作为 AI 质量指标。每批候选至少检查：事实可回源、问题原子性、答案泄漏、重复/近重复、题型语义、难度理由、语言正确性、危险建议、隐私外发和用户接受率。低质量候选应进入修订收件箱，不直接进入正式队列。

### 5.1 用户可见的 AI 任务体验

AI 继续贯穿全生命周期与每个模块；以下体验把全局策略落实到用户每次选择、审核与返回的动作中。页面组织见 [32-产品体验优化与页面蓝图](./32-产品体验优化与页面蓝图.md)。首批可围绕问答/挖空实现一条完整任务链，后续解释、应用、语言、维护、课程与系列联动沿用相同边界，按任务增加更细的输入和输出。

| 决策点 | 用户应看到与控制 | 复用条目/主职责 | 最小验收与手工路径 |
|---|---|---|---|
| 选择任务 | 按“做关键卡/理解材料/改好这张卡”等目的选任务，查看适用条件、产出示例与推荐理由；模型和提示词参数渐进展开 | BU-5/34、BV-2/4；模板质量 | 只展示当前已验证任务；可改选和锁定意图；同一任务不因 provider 不同藏起提示词入口；无 AI 用人工/规则配方 |
| 准备材料 | 来源名称、片段、版本与范围可展开；可编辑、移除、替换或追加，保留返回点 | AQ-18、BU-6/36、BI-3；调用安全/目标旅程 | 可见预览与实际请求对齐；范围或端点变化重新检查，拒绝不发送；手工编辑使用相同材料选择 |
| 决定生成量 | 关键最少/数量上限/覆盖优先、候选重点、排除项、覆盖缺口及可核验负担估算 | BA-11、BV-1/5；目标旅程主责，制卡编辑引用 | 不强迫达到数量；缺数据为未知，不预测 due；用户可分批、缩小范围或人工选点 |
| 审核候选 | 题面/答案/来源可对照，问题优先浏览；选中、待审、已审、已编辑、拒绝和稍后状态分别显示 | AQ-16、BU-10/13/14/42；模板质量/候选治理 | **选中不等于已审**；按当前任务审阅策略完成确认，未审不入正式队列；键盘与窄屏可继续；规则与人工草稿共用审核动作 |
| 处理未知与冲突 | 在受影响内容旁显示材料缺失、来源冲突、术语不清或格式问题及修复动作 | BU-10/11/12、BV-3；模板质量/研究证据 | 可补材料、回源核查、编辑、拒绝或保留待核实；不以模型自信度替代引用，手工也可并列来源与标记未知 |
| 定向修改 | 当前卡身份与知识点、本次意图、人工锁字段、逐项差异与引用 | BX-2、BU-15、BV-5/6/19；制卡编辑 | 改写不换知识点、不覆盖锁字段，逐项接受或拒绝；失败保留人工版本；无 AI 可局部编辑并比较差异 |
| 等待与中断 | 材料检查/等待/生成/待审/写入/部分成功等真实阶段，已完成范围及可停止、稍后或重试动作 | AQ-14/17、BL-3、BU-24—30、AS-4；作业候选 | 不用虚假百分比或 toast 冒称完成；取消保留草稿，说明已产生或未知费用，恢复不重复执行；本地任务用同一状态语义 |
| 完成与交接 | 已创建/待审/失败/未执行分别展示，显示目标位置、可打开对象、恢复/撤销及试练/回来源/收工动作 | BI-6/17、BU-39、AQ-17；目标旅程/作业候选/Agent | 结果不能以关闭向导加 toast 结束；计划不冒充已执行；传递本次已确认意图、限制及未决问题，用户可移除，不默认存长期记忆；人工创建同样可回到落点 |
| 首次了解 AI | 用固定材料与固定候选走一次选任务、范围预览、审核、编辑、结果和失败后的继续路径 | BX-5、BE-2、AU-6、BU-40；上手帮助 | 无 key 可运行的本地样例明确标“样例结果”，不发模型请求、无模型费用、不创建正式复习或评分事实；用户主动转为真实任务后重新选范围与确认；同时提供人工版本 |

所有模型建议均可编辑、人工拒绝或跳过，AI 入口保留可完成同一核心目的的手工路径及能力损失说明。任务本身、人工确认、来源选择、负担估算与作业状态由本地业务事实控制，不让模型先处理原文再决定权限或猜测操作完成。普通 AI 任务按自身 G3-call/G3-quality 验收；Agent 还需 G3-agent，宿主缺能力时显示原因并退到普通 AI 或手工。上述体验深化既有 BU/BV 等验收，不以新页面为理由另建调用层、记忆平台或评测服务。

## 6. AI 数据、权限和成本

每次请求都应形成可脱敏的 `AIInvocation` 记录：模板 ID/版本、模型/端点、输入范围哈希、来源数量、输出计数、token/耗时、是否外发、用户确认、结果和错误。默认不保存原文和完整 prompt；用户主动开启调试时才短期保留，并提供清除动作。

调用前展示：将发送哪些材料、发送到哪里、预计 token/费用、是否保存、失败如何恢复。规划支持本地模型、思源 Agent、配置端点和无 AI 手工降级；低带宽时优先文本草稿，媒体和长上下文分层请求。多模型按任务路由时，应明确质量、隐私、延迟和成本取舍，禁止因主模型失败而静默切换未授权端点。

## 7. 评估与发布门禁

评测 fixture 从任务、提示词、schema 和权限的设计期建立，与调用实现并行推进。先使用脱敏样本、固定响应和 mock provider 检查引用错位、答案泄漏、重复建卡、提示注入、敏感边界、拒答、越权、取消与恢复；离线/mock 证据只证明本地边界，不代表真实模型质量或真机通过。外发范围、用户同意、端点、预算、取消和安全条件满足后，才进行该任务的真实模型评测。

模型、提示词或解析器变化在成为默认版本或发布前，必须通过版本化任务 fixture 和安全回归。覆盖范围按本次能力选择，并至少包含适用的事实幻觉、引用错位、答案泄漏、重复建卡、恶意提示注入、敏感信息外发、中文/英文/混排、长文截断、低网速、取消/重试、旧模板迁移和 Agent 越权场景。

G3 按能力拆开验收：**调用安全**检查 eligibility、上下文预览、consent、provider、预算、取消/降级和审计；**任务质量**检查该模板的来源、输出 schema、质量 lint 与人工审阅；**Agent 专项**检查宿主协商、schema/effects、工具范围、次数上限和行动账本。普通 AI 任务无需等待 Agent 门禁，无 AI 的业务路径无需 G3。缓存、模型比较台、多模态、分享和长期记忆等扩展只约束相应能力，不作为所有 AI 调用的统一前置。

产品指标分开记录：候选接受率、人工修改率、引用覆盖率、重复率、失败率、恢复率、token/卡成本、用户节省时间，以及 AI 生成批次后真实回忆/应用证据。任何指标都不能单独宣称“提高记忆”。

## 8. 分阶段路线

1. **当前可靠性与最小契约**：先记录本次变更的 owner、事实源、宿主版本、写入边界和回归样本，立即推进真实 P0 修复；完整能力地图、V2/多端矩阵和 mock 基础持续完善。现有 AI 制卡的外发、取消、降级和批次恢复问题与核心可靠性并行治理。
2. **手工旅程与 AI 最小切片并行**：建立目标→材料→候选→审核→制卡→复习→报告→回源的手工路径；同步建立统一 AIInvocation、权限预览、任务模板、schema、证据、取消/重试和手工降级的最小入口。从现有制卡选一个任务通过调用安全与任务质量门禁，fixture 从设计期开始，不等后续融合期才评测。
3. **逐模块融合**：解释、维护、语言、课程、应用和报告按用户价值、业务数据与各自 fixture 逐任务接入，复用统一调用层；本次业务切片不用等待 BV 全部 24 项完成。Agent 探测并行，只读 handler 在权限/schema/审计成立后注册，确认型计划再过 Agent 专项门禁。
4. **互通与结果研究**：在相应宿主和事件契约成立后增加系列编排、第三方模板/能力包/模型适配器；缺宿主时降级普通 AI 或手工。取得真实回忆、解释、应用证据后，再比较模板/模型与学习结果的关系，记录样本量、分母、偏差和未知，不把相关性写成因果。
5. **逐能力发布与复评**：每个经过必要门禁的能力可独立进入发布子集，并同步状态、隐私、帮助和限制；第三方扩展、签名、分享、长期记忆等仅在本能力需要时增加专项门禁，后置能力登记复评条件。

AI 能力越强，越需要让用户知道“它看到了什么、依据什么、建议什么、会改变什么、失败后如何回来”。这是小驴区别于普通 AI 制卡工具的核心体验。

## 9. 无 AI 等价流程（BU-40，v0.200.0）

每个 AI 入口都登记手工/规则替代路径与损失说明，单一事实源为 `src/core/ai-equivalents.ts`（AI_EQUIVALENTS 注册表，i18n 键 `aiEquiv.*`，zh/en 对齐）：

| AI 制卡向导（cards-generate） | 是 | 快速问答制卡 / 标记符制卡 / Anki 整包导入 | AI 的批量提炼与措辞改写；替代路径需自行提炼，耗时更长 |
| 烂卡 AI 改写（leech-rewrite） | 是 | 手动按修卡演练三步法改写 / 删除重建 | AI 的改写建议；复习事实与正式评分完全不受影响 |
| 修卡演练（repair-drill） | 否（显式声明） | —（自身即零网络零写入的教学路径） | — |
| 全程不使用 AI（no-ai） | 否 | 所有核心功能（复习/调度/统计/导入导出）无需 AI 完整可用 | — |

约定：新增任何 AI 入口必须先在注册表登记（usesAI/替代路径/损失说明），tests/ai-equivalents.spec.ts 防漏登记；eligibility 阻断信息、设置帮助与用户文档引用同一注册表键，不允许出现「只在此处可查」的替代说明。
