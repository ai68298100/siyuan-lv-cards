# 架构决策记录（ADR）

> 记录影响深远、回退成本高的决策。每条含：背景 / 决策 / 后果。变更须新增条目并标注取代关系，不修改旧条目。

## ADR-1 双轨 Gateway（riff ↔ flashcardV2）

- 日期：2026-10-01 · 状态：Accepted
- **背景**：思源 3.8.x 稳定线只有 riff API（17 端点）；feature/flashcard 分支（3.9.0）引入 42 端点的 V2 体系与迁移状态机。用户分布跨两个内核线。
- **决策**：`FlashcardGateway` 抽象后双轨并存——运行时 `detectFlashcardV2()` 探测（结果落库 `settings.gatewayState`，重探广播 `lv-cards:gateway-changed`）；默认走 riff，V2 激活才启用增强。插件永不自建调度（ADR-3）。
- **后果**：+双内核线用户即装即用，V2 到来零迁移；−每个能力要做能力矩阵判断，riff 路径部分功能标注 V2-only。

## ADR-2 UI 必须 Kit 装配（Starline 设计系统）

- 日期：2026-10-01 · 状态：Accepted
- **背景**：功能面快速扩张（19+ 组件、多屏），无统一装配规则会碎成一次性 CSS。
- **决策**：新界面只允许组合 docs/16 组件库；缺件先补 Kit 再用；设计令牌全部派生自思源 b3 变量（color-mix），不引入独立主题。
- **后果**：+亮暗主题免费、视觉一致、组件可回归；−新屏先补组件的前置成本；裸 b3 类存量渐进迁移（控件组 v0.60 起标准化）。

## ADR-3 内核是唯一调度源，插件只做增值层

- 日期：2026-10-01 · 状态：Accepted
- **背景**：内核 riff/V2 已实现 FSRS 调度与原生复习界面；自建调度会造成双数据源漂移。
- **决策**：评分/排程永远调内核（riff reviewRiffCard / V2 reviewFlashcardV2）；插件侧的"忘记卡本批重现"等强化只做本地展示层，不重复评内核、不写平行 revlog 到内核。
- **后果**：+卸载插件零残留、与官方复习界面互通；−会话内强化类功能只能"不计调度"实现。

## ADR-4 主包体积预算 ≤32KB gzip（CI 门禁）

- 日期：2026-10-01 · 状态：Accepted
- **背景**：移动端首开性能；曾因考试页引入涨到 39KB。
- **决策**：`dist/index.js` gzip ≤32KB 由 CI 强制；重组件（设置/向导/遮挡/挑战/配对/标记/考试页等）一律懒加载 chunk；文案类大常量入 i18n 或独立 chunk。
- **后果**：+首开可控、增长需评审；−每次加功能要留意 chunk 划分（v0.55/0.59/0.61 三次压回预算内）。

## ADR-5 数据契约：本地优先 + 结构清洗 + 幂等合并

- 日期：2026-10-01 · 状态：Accepted
- **背景**：revlog/settings 等私有数据跨设备同步（思源同步），多端写入存在分叉。
- **决策**：所有存储文件 load 时过 normalize（TypedStore 入口 `libs/store.ts`，非法结构落 fallback 绝不阻塞启动）；未知字段保留（只增不删）；revlog 合并按 ts+cardID+rating+source 去重，评分冲突（分叉）默认跳过、可「以导入为准」幂等重放。
- **后果**：+损坏文件不白屏、升级/downgrade 均安全、多设备冲突可控；−清洗代码是每个数据文件的必付成本。

## 候选 ADR-6 跨前端同步重载协议（AT-1 预研）

- 日期：2026-10-03 · 状态：**Proposed（候选）——待宿主契约确认，未实现、不改运行代码**
- **背景**：思源同步会把 `data/storage/petal/siyuan-lv-cards/` 下的私有数据在设备间同步；插件当前未覆写 `onDataChanged`。旧版 Petal 契约可能默认整插件重载（丢 Tab/面板状态），且旧签名无 reason 参数，无法区分「同步写入/本地写入/其他」。
- **提案草案**（实现前须逐项确认宿主行为）：
  1. **触发与版本探测**：覆写 `onDataChanged(key)` 按 key 粒度入队；以「磁盘内容 hash ≠ 内存态 hash」判定确实有远端变化，避免无谓 reload。
  2. **有界串行 reload**：每 key 单飞（复用 persist 队列的反向模式）——先 `persist.waitAll(短预算)` 冲刷本地未落盘写入，再 `loadData → normalize → 原子替换内存态`；normalize 全走既有 TypedStore 入口（ADR-5），损坏远端数据不白屏。
  3. **不覆盖未 flush 本地写**：某 key 有在途写入时跳过该 key 的 reload 并在 flush 完成后重新入队（本地新写入优先，远端由下一次同步事件再收敛）。
  4. **合并策略**：settings 逐字段（normalize 已兜底类型）；revlog 走 `mergeRevlog` 幂等去重（同 ts+cardID+rating+source 跳过，分叉默认保守）；session-state 取 date 较新者；suspend/exam/ai-batches 整体替换（normalize 后）。
  5. **Tab 保持与失效**：reload 只替换内存态，UI 通过既有事件（settings-changed / lv-cards:reviewed / session-finished）自刷，不 remount Tab。
  6. **失败与重试**：reload 失败进 persist 的 onFail 通道（lvLog + 限流提示），有限重试后放弃本次，等下一同步事件。
- **待宿主确认的开放问题**：reason 参数取值与语义（sync-start/end/fail 是否可辨）？回调时 loadData 读到的是否已是同步后原子内容？双窗口/移动端各自收到回调还是仅主窗口？整插件重载是否可在 manifest/配置层关闭？
- **决策门槛**：以上问题经 3.8/3.9 真机 fixture 确认后，才能把本候选转为 Accepted 并排期实现（验收见 [17-待办清单](./17-待办清单.md) AT-1）。
