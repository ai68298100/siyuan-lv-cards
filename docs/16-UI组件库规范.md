# 小驴闪卡 · UI 组件库规范（Lv Kit）

> R50 · 组件装配规格 v1.0（2026-10-02）。配套：[32-产品体验优化与页面蓝图](./32-产品体验优化与页面蓝图.md) v1.0；排期以 [30-待办治理与执行顺序](./30-待办治理与执行顺序.md) v1.2 为准。本轮只更新规划，配方和目标状态不能当作当前组件已支持的证据。
>
> **新界面优先复用 Kit 组件与宿主语义**：先组合既有组件和领域样式，缺通用能力时再按 §5 扩展。复用不等于强迫使用不合适的组件，不能以装配率替代任务完成与可访问性。
> 三层结构：`令牌（index.scss 的 --lv-*）→ Kit 组件（src/ui/kit/）→ 业务屏幕（src/ui/*.svelte）`。
> 视觉规格见 15-视觉设计系统；交互行为见 12；本文是"有什么、怎么用、什么时候用哪个"。

## 1. 分层与规则

| 层 | 位置 | 允许 | 禁止 |
|---|---|---|---|
| 令牌层 | `src/index.scss` | `--lv-*` 变量、共享类（.lv-card2/.lv-btn-primary/.lv-tabs/.lv-table/.lv-skeleton…） | 出现业务专属选择器 |
| Kit 层 | `src/ui/kit/Lv*.svelte` | 组合令牌与 b3 类；通用、无业务语义 | import 业务模块（api/core） |
| 屏幕层 | `src/ui/*.svelte` | 组合 Kit + 领域样式（复习卡面等专属渲染） | 手写页面容器/分区/表格/空态等 Kit 已覆盖的结构 |

Do & Don't：

- ✅ 新屏幕先在本文 §4 找"装配配方"；通用能力缺口先评估现有 Kit/b3，再补最小 Kit 能力
- ✅ 颜色只用 `--lv-*`/`--b3-*`；间距只用 `--lv-sp-*`；动效只用 `--lv-dur-*`/`--lv-ease`
- ❌ 不硬编码色值（阴影/遮罩的 black/white 透明梯度除外）；不复写 Kit 内部样式（ gap/prop 不够就改 Kit）
- ❌ Kit 组件不做数据请求、不弹消息——数据与副作用永远在屏幕层

## 3. 组件状态与可达性基线

- 可交互组件：可见焦点、文字/图标语义、键盘/触控等价；hover/短反馈为可选增强。静态数据不显示导航箭头或可点击式 hover；评分档位保持同级。
- 禁用态：提供 `disabled` 或适当语义、可读原因和下一步。不能只降 opacity，也不能在不可聚焦的控件 title 中藏唯一说明；依赖不可用、权限拒绝和进行中分别解释。
- 加载态：屏幕级用 `.lv-skeleton` 骨架（见总览/管理器），按钮级用 b3 原生 loading
- 错误态：可读原因、保留现场和合法动作；已有结果刷新失败应保留过期数据，不能清成空态。未知、失败、取消、未审和成功语义分开。
- 动效：全部经 `--lv-dur-*`（reduced-motion 归零）或包 `no-preference` 守卫
- 焦点：表单关联 label/hint/error，Tabs 与对应 panel 互相关联；模态/非模态层分别处理移入、循环和关闭后归还。组件当前未具备的语义需补验收，不能只在文档写已支持。
- 主题与对比：派生令牌仍须亮暗/第三方主题/缩放实测；小屏、低性能可用纯色、无 blur 和静态反馈。

## 4. 装配配方（后续屏幕照此拼装）

### 4.1 闪卡中心与今日任务（当前骨架 + 规划）
```
LvPage(title=闪卡中心)
  └ LvTabs(tabs=[总览,管理,可选考试], active, onchange)
  └ {#if active==='overview'} 总览内容（现 dashboard 主体）{/if} …
```

当前 Hub 为上述三类入口，数据任务面未实现。规划把总览首屏改为今日目标/时间/上次现场和下一动作，统计按需展开；材料、结果、待处理通过任务卡/对象上下文/命令进入，不因功能增长强加 Tab。切页与错误边界重建均需保留状态，详见 32 与 AS-9/BI-17。

### 4.2 材料与候选审核（当前两画面；扩展为规划）
```
短任务 Dialog / 长审核工作面（按任务选择）
  LvSteps（仅在顺序明确时）：当前配置 → 候选
  材料态: LvSection(可编辑实际材料、逐项来源、替换/追加)
  任务态: LvSection(模式、授权范围、预算、进度/取消)
  审核态: LvSection(来源 + 编辑 + 问题/答案真实预览 + diff)
  结果态: LvSection(逐项结果、检查点、继续/修复/返回)
```

材料、任务、审核、结果是可恢复状态，不规定固定步数或同一容器。选中不等于已审，确认写入和拒绝/待核实分开；窄屏切次级面仍保留同一卡身份。实际材料编辑与复习渲染预览当前存在缺口，不能用配方宣称已支持。统一取消/Promise/失败草稿按 AR-2/AQ-14/17 验收。

### 4.3 考试子页（M7）
```
LvPage(title=考试, actions=[新建计划])
  计划卡 = LvCard2 + LvProgress(倒排进度) + LvChip(滞后预警 warn/error)
  今日应学 → openReview(计划范围)
  倒计时 = LvChip(primary) + 呼吸点
```

### 4.4 待处理与恢复任务面（规划）
```
上下文任务卡 / 全局命令 → LvPage(待处理与恢复)
  LvSection(本次作业、影响范围、检查点、合法下一步)
  按需展开: 维护 / 同步冲突 / 备份恢复 / 权限 / 高级诊断
```

共用发现入口，不合并各事实源：BL-3 作业、BI-25 维护、BL-10 恢复、BL-5 权限仍按各自主包验收。当前数据操作主要分布在设置等入口；不能写成已存在的独立数据 Tab。

### 4.5 首次引导（Onboarding）
```
可跳过的目标/材料入口 → 手工或本地示例首卡 → 首场/结果/下一步
```

画像、固定三张或固定三步只是示例；关闭/稍后/跳过不冒充成功，样例创建失败可继续且幂等。采用 Dialog 还是工作面按任务和设备验证。

### 4.6 移动端
```
LvPage + 断点/容器布局（padding 与 --lv-sp 配合）；悬浮球按实际支持能力单独验收
```

这是目标配方，不代表自动通过窄屏验收；按 320px、字号放大、safe-area、输入法、手势/滚动冲突与读屏分别验证，悬浮球能力以实际状态登记。

### 4.7 设置搜索与本地效果预览（BX-4，规划）

以 `LvPage/LvSection/LvRow` 组合任务分组、搜索定位、字段与可读说明；`LvInput/LvSelect/LvSwitch/LvSlider` 复用控件。搜索结果展示所属路径、禁用原因、覆盖值与生效时机；预览只用本地脱敏样例，取消不写真实内容。固定动作区显示变更数、保存状态和按项恢复；保存失败保留草稿，不关闭。

BX-3 的本场偏好与全局默认/目标范围覆盖分开显示；同一模式选择不由多个开关的隐式优先级决定。复用现组件后再判断需不需要新增，不能先列一批不存在的组件。

### 4.8 结果与下一步（规划）

`LvSection` 展示本场结果、真实剩余、问题与依据；清楚区分正常收工、中断、未知和失败。来源/异常可进入对象详情和修复，用户可结束或稍后，不强推再来一批。数字须有时间窗/分母/缺失说明，图表有可读表；真正可钻取的卡才显示链接语义。

## 5. 新组件准入流程

1. 先问：现有 Kit + b3 语义能否完成该任务和状态？不使用未经测量的复用比例做承诺。
2. 确需新增：在 `src/ui/kit/` 建 `LvXxx.svelte`，零业务依赖，样式只用令牌
3. 本文目录表 + 装配配方同步更新（否则 PR 不合）
4. 命名：`Lv` 前缀 + PascalCase；CSS 类 `lv-` 前缀 + kebab-case；令牌 `--lv-` 前缀

## 6. 现状盘点

- R50 核对目录为 19 个组件与 1 个工具；新增/删除文件后同步目录，不能保留旧“10 组件”计数。
- 总览、管理、设置、复习及 AI 等页面已有不同程度复用，可用于审阅源码；装配不证明焦点、Promise、实际材料预览、窄屏和主题验收完成。
- §4 的未来任务面优先复用，允许有证据的最小扩展；不保证零新组件。是否成套以用户任务、成功/失败/取消、语义和恢复的完整验收为准。
