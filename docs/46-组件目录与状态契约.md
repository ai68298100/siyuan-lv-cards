# 小驴闪卡 · 组件目录与状态契约

> 本文由 `src/ui/` 当前源码反向整理（2026-10-13），用于查询组件用途、Props/回调和责任边界。UI 结构、视觉、文案、交互状态与响应断点以唯一规范 [R54 原型](./prototypes/lv-cards-r54.html)为准；本目录不另立 UI 规范。原型中的固定样例不代表运行时数据或服务能力。
>
> 数量基线：`src/ui/kit/` 有 23 个 Svelte 组件和 2 个 TypeScript 工具；`src/ui/` 根目录有 25 个业务 Svelte 组件。新增、删除或改名后应同步本表。

## 1. 统一状态约定

| 状态 | 组件层约定 | 责任边界 |
|---|---|---|
| 空闲 | 控件可操作，显示当前数据或表单草稿 | 页面负责校验前置条件和可操作性说明 |
| 加载中 | 屏幕级优先骨架，按钮/表单锁定重复提交 | 数据请求和取消、超时由页面或宿主服务负责 |
| 成功 | 显示结果、成功提示或进入明确下一步 | 写入成功以宿主回执为准，不能仅凭点击推断 |
| 失败 | 可读原因、保留现场、可重试入口 | 组件不吞异常；宿主区分网络、校验、权限和服务错误 |
| 空结果 | 明确说明没有数据，并给出下一动作（适用时） | 不把加载失败或未知状态渲染成空结果 |
| 不适用 | 纯展示、布局或由父组件控制的组件不伪造异步状态 | 在业务屏幕记录真实状态和调用方责任 |

所有 `disabled` 只表示当前不能触发；原因必须由邻近文案、错误态或可访问名称解释。业务组件的成功/失败是否持久化、是否回滚，由传入回调的返回值和宿主服务决定。

## 2. Kit 组件

Kit 组件不直接请求数据、不调用业务 API、不弹业务消息；它们只渲染 props 和派发用户动作。

### 2.1 交互元素清点

这是接手和验收时的交互元素索引。R54 原型规定这些元素的布局、视觉、文案、断点和状态；下面的源码位置负责实现动作和数据回执。

| 元素类别 | 当前实现位置 | 必查行为 | 状态责任 |
|---|---|---|---|
| 主导航、页签、返回入口 | `hub.svelte`、`LvTabs.svelte`、各页 `navBtn` | 主导航用 `aria-selected`；收件箱侧栏/顶栏入口与学习子导航用 `aria-current="page"`；点击、方向键/Home/End、Esc/返回、深链和刷新后仍定位到正确页面 | `hub` 负责懒加载/切换失败；页面负责保留筛选、滚动、焦点和草稿 |
| 主按钮、次按钮、危险按钮 | `src/ui/*.svelte`、`LvDrawer.svelte`、`lvConfirm.ts` | 每个动作有前置条件、处理中锁定、成功归宿、失败文案和可重试入口；危险动作二次确认 | 调用方提供异步回执、回滚/撤销和权限错误；Kit 不猜测写入成功 |
| 图标按钮、关闭/更多按钮 | 页面 actions、`LvDrawer`、命令面板 | 有可见或 `aria-label` 名称、悬停提示（必要时）、键盘可达；关闭后焦点归还 | 关闭/取消不应丢弃未保存草稿；异步关闭由页面确认完成后执行 |
| 链接与来源回源 | `dashboard.svelte`、`review.svelte`、`card-detail.svelte`、`maintenance-page.svelte` | 目标文档/块正确；返回时恢复 `page/query/filters/scrollAnchor/focusId` | 宿主提供来源打开和权限错误；找不到来源显示可读占位而不是空白 |
| 表单输入、文本域、日期/数字、滑杆、开关、分段 | `LvInput`、`LvSelect`、`LvSlider`、`LvSwitch`、`LvSegmented` 及 goals/exam/settings/制卡页 | 输入时机、字段级错误定位、极值/空值/特殊字符边界；提交中防重复；保存失败保留草稿 | 页面负责校验和错误关联；宿主负责保存、幂等、回滚和缓存失效 |
| 下拉、筛选、搜索、标签 | `manager.svelte`、`deck-picker.svelte`、`LvPalette.svelte`、原型 `library` | 空选项、筛选无结果与空库区分；搜索回第一页；清除筛选有反馈 | 数据读取失败必须显示错误/重试，不得伪装成空结果；旧请求不得覆盖新筛选 |
| 弹窗、抽屉、确认框 | `LvDrawer.svelte`、`card-detail.svelte`、`ai-wizard.svelte`、`lvConfirm.ts` | 打开、关闭、Esc、焦点陷阱/归还、滚动边界；删除/清空/覆盖/退出的影响说明 | 内容加载/保存错误由调用方显示；取消只关闭，不提交或清理未确认数据 |
| 卡片、表格行、批量栏、分页器 | `manager.svelte`、`card-detail.svelte`、原型 `library` | 行点击与行内按钮不冲突；checkbox、Enter、Delete、批量确认；分页/筛选后回第一页并保留现场 | 列表加载骨架、错误重试、空库/筛选无结果分开；写成功精确失效列表缓存 |
| 日历、热力图、统计卡、状态标签 | `LvCalendar`、`LvHeatmap`、`LvStat`、`LvChip`、dashboard/learning | 未知值显示 `—` 和原因；点击日历有范围反馈；状态不只靠颜色 | 统计缺失/部分失败由页面说明口径；纯展示组件不伪造加载或成功 |

## 3. 业务屏幕与工作流

业务组件可请求 API 或持有页面状态，但数据服务、缓存、鉴权和持久化仍由宿主/服务层提供。下表中的“状态”只记录源码已实现的界面分支。

## 4. 维护规则与未覆盖项

1. 新业务屏幕先复用 Kit；若新增通用状态，必须同时补充 `$props()` 类型、失败/空态行为和本目录。
2. 本目录不替代端到端验收。路由深链/刷新、真实服务商错误分类、鉴权恢复、网络请求统一去重/取消/重试、写操作幂等与回滚，必须在宿主服务和验收台账中验证。
3. “成功关闭”只表示组件回调完成后关闭；没有回调回执的按钮不能在文档中宣称写入成功。
4. 原型 `docs/prototypes/lv-cards-r54.html` 是 UI 规范事实源，但不连接思源内核、AI 服务或真实卡组，不能作为生产数据或接口契约。发现原型与生产 UI 不一致时，先在 docs/45 记录差异，再同步修复原型和实现。
5. Kit 的空态、错误态、加载态是可组合基元；是否显示以及文案、重试策略由业务屏幕根据真实数据决定，不能为了满足表格而伪造不适用状态。
