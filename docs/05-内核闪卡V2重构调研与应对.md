## 3. V2 概念模型（重大变化）

- **Source（源）/ Card（卡）分离**：一张源（块+模板）可产出多张卡（`templateID` + `variantKey/variantData`，`generationStatus` 跟踪生成）——对齐 Anki 的 note→cards
- **ReviewSet（复习集）取代 Deck**：支持 `queryAST`（**查询驱动的动态牌组**≈Anki 筛选牌组）、`order`（priorityDue/due/added/**random**）、**每集 newLimit/reviewLimit**
- **ReviewState 直接暴露 FSRS 内部量**：`Stability / Difficulty / ElapsedDays / ScheduledDays / Due / State / Reps / Lapses / Suspended` ——旧 riff 不给 S/D 的缺口没了，**影子估算方案作废**
- 卡模型还有：`Flag`（旗标）、`PriorityOverride`（优先级覆盖）、`EditLater`（稍后编辑+备注+revision）、`PresetOverrideID`（每卡策略覆盖）
- 卡型是开放体系：内置 basic 等 + **插件可注册自定义卡型**（见 §4）
- 配置新增：`AnkiConnectEnabled`、`AnkiConnectLocalWithoutKey`（可信本机免密）、`AnkiConnectNotebook`（第三方卡正文的落账笔记本）、`OpenMode`（0 弹窗/1 页签/2 右侧分屏/3 新窗口）

## 4. AnkiConnect 兼容（`POST /api/flashcard/ankiConnect`）

- 思源**扮演 Anki**：AnkiConnect 协议形状（`{action, version, params}` → `{result, error}`），支持 multi 批量
- 已实现 action：`version / apiReflect / multi / deckNames / deckNamesAndIds / createDeck / modelNames / modelFieldNames / addNote / addNotes / canAddNotes / canAddNotesWithErrorDetail / notesInfo / findNotes / updateNoteFields / storeMediaFile`
- 意义：**Anki 生态的第三方工具（含 AI 制卡流水线）可以零改造对准思源**；`storeMediaFile` + 48MB body 上限说明媒体通路已打通；apkg 导入（preview/import 两段式）也是配套

## 5. 前端插件扩展点：`registerFlashcardV2PluginType`

官方前端暴露正式的**自定义卡型注册机制**：

```ts
registerFlashcardV2PluginType(namespace, {
    typeName,
    render?:  (ctx: {sourceType, model, doms, frontElement, backElement}) => {hasAnswer?, revealController?, answerController?},
    create?:  (ctx: {blockIDs, reviewSetIDs}) => void,
    edit?:    (ctx: {sourceType, model, doms}) => void,
})
// sourceType = `plugin:<namespace>:<typeName>`，如 plugin:lv-cards:type-answer
```

- `revealController` → **图片遮挡的显隐控制**有了官方口子；`answerController.check` → **打字题判分**有了官方口子
- 这直接改写我们题型路线：不再自建复习面板渲染题型，而是**以 V2 卡型插件的形式实现**打字题/选择题/遮挡，复用官方复习会话 UI

## 6. 对小驴闪卡的影响与应对（定位重划）

### 6.1 官方已做 → 我们不做或转型

| 原规划 | V2 现状 | 应对 |
|---|---|---|
| 统计仪表盘（D1-D9） | 内核 `getStatistics`：overview/时间线/小时分布/forecast/四种 FSRS 分布/leech | **转型为"官方统计的高级消费端"**：更专业的图表呈现、跨期对比、周报月报导出、卡组横向对比；保留本地 revlog 作历史累计（启用日更早于 V2 的场景） |
| 影子 FSRS 引擎（B2） | ReviewState 直出 S/D/R | **砍掉**，直接读内核值 |
| 撤销评分（C6） | `undoReview` 端点 | 用官方端点 |
| 烂卡清理（E5） | inspectInvalidSources / deleteInvalidSources | 用官方端点 |
| Anki 导入（F1） | 内核 previewAnkiPackage / importAnkiPackage | **砍掉自研 apkg 解析**；插件转型做"导入向导/字段映射增强/导入后清洗" |
| Anki 导出（F2） | ankiConnect 反向兼容（外部 Anki 工具直连思源） | 插件可做 AnkiConnect 客户端配置面板/状态监控 |
| leech 识别（E4） | statisticsLeechThreshold + Flag | 用官方 |
| 随机顺序（C16） | ReviewSet.order=random | 设置引导而非自实现 |
| 图片遮挡（A7/C18） | 官方有 inline occlusion（flashcardV2Occlusion）+ V2 插件 revealController | 改为 V2 卡型插件增强（与官方内置差异化：多区域组合、答案键盘导航等） |
| 打字题（C8） | V2 插件 answerController.check 官方口子 | **实现为 V2 卡型** `plugin:lv-cards:type-answer` |

### 6.2 官方没做 → 我们的主战场（相对市场调研不变）

- **AI 制卡**（A8/G1-G4）：官方 generation.generationStatus 表明有生成管线，但无面向用户的 AI 生成向导 → 我们的 AI 制卡（多源输入+预览+批量接受）仍是差异点，且可用 `createAdvancedSource` 落卡
- **考试 deadline 倒排**（B9）：完全空白，StudyPolicy 是挂载点
- **游戏化**（H 组）：完全空白
- **题型交互增强**：三档评分、超时模式、滑卡手势、白板、配对/限时挑战 → 部分可作为 V2 卡型/官方会话增强实现
- **统计增值**：遗忘曲线个人 vs 理论对比、周报生成、跨设备长期档案
- **AnkiConnect 生态桥**：配置面板、同步状态可视化、与第三方 AI 制卡工具的衔接说明

### 6.3 技术架构调整

1. **双 API 层**：`api/riff.ts`（现有，兼容态可用）+ `api/flashcardV2.ts`（新）；启动时 `getMigrationStatus` 探测（404=未升级到 3.9；返回 state=迁移状态），能力矩阵驱动 UI
2. **迁移状态可见化**：仪表盘显示 V2 状态徽章（Legacy/Preparing/Active/LegacyDiverged），LegacyDiverged（迁移后旧 API 侧又有写入）时提醒用户
3. 复习/管理主路径：V2 Active 时逐步切 `startSession/getSessionQueue/reviewCard/undoReview` 与 `queryCards`；riff 路径保留兜底
4. UI 仍用自有 Tab/Dock（官方 flashcardTab 的 OpenMode 与我们互补），但**题型渲染遵循 V2 卡型注册机制**而非接管官方面板

## 7. 版本策略

- v0.1（当前）：riff 路径 + V2 能力探测 + 状态徽章（本次已实现）
- v1.0：等 3.9.0 beta 落地后，仪表盘切 `getStatistics` 做高级可视化；管理器切 `queryCards` AST 搜索
- v1.x：AI 制卡接 `createAdvancedSource`；打字题/遮挡以 `plugin:lv-cards:*` 卡型注册；考试模式挂 StudyPolicy
- 风险：分支未合回 dev，契约仍可能变动（`kernel/flashcard/plugin_test.go` 说明官方在测插件路径）；我们的 V2 封装保持"宽容解析 + 可降级"
