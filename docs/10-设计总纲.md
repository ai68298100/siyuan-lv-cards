## 1. 定位与终局愿景

**小驴闪卡要成为思源生态最全面的闪卡学习平台。**

它覆盖材料捕获、知识加工、卡型生成、间隔复习、主动回忆、应用练习、课程/考试规划、统计诊断、内容维护、数据迁移和小驴系列联动。用户可以从任意材料开始，也可以在任意学习阶段进入；闪卡是核心载体，完整学习生命周期是产品范围。

**AI 与思源 Agent 是核心产品能力。** 各模块都要设计 AI 可以减少什么负担、使用什么来源、生成什么候选、在哪一步由用户决策；内置提示词按具体学习任务优化，统一进入 AI 编排层，不能只在制卡向导考虑 AI。

内核（含 3.9.0 闪卡 V2）负责正式卡片数据与调度权威——卡是什么、何时复习；小驴闪卡负责把材料变成卡、把卡放进合适的学习流程，并补足练习、目标、维护、互通和平台体验。

> 一句话：**让思源成为从知识捕获到长期掌握的全域闪卡学习平台。**

实现策略：先建立完整能力地图，再按“当前宿主稳定可实现 → 依赖官方/V2 → 依赖外部服务或社区生态 → 长期探索”分层交付。当前做不到的能力进入后置池，记录依赖、替代方案和复评条件，不能被误解为永久放弃。

技术边界（决定实现方式，不缩小愿景）：
- 不伪造宿主能力、不绕过官方调度所有权；正式 due、评分和间隔在当前宿主契约下以内核为权威
- 官方已有能力优先调用并编排，不重复造第二套事实源；需要跨工具或离线镜像时通过迁移契约接入
- 云服务、市场、多人协作、完整增量阅读等进入后置池，条件成熟后复评，不从终局能力地图删除
- 不暗中上传学习数据；外部 AI、媒体、联系人和生态写入均需逐次授权
- AI 是贯穿全生命周期的受控辅助层：按任务使用内置模板与思源 Agent，输出先引用/校验/人工确认；模型、提示词、成本、外发和失败降级均可追踪，不能直接改变正式调度

## 2. 用户画像与场景

| 画像 | 核心诉求 | 主用模块 | 关键旅程 |
|---|---|---|---|
| P1 备考学生（考研/考证/医考） | 别让我积压；考前必须过完一遍 | 考试模式、复习面板、AI 制卡、cram | 导入讲义→AI 成卡→按倒排进度学→考前 cram→考后复盘 |
| P2 卡片笔记党（知识工作者） | 制卡要快；数据要看得见 | 制卡工作流、统计中心、管理器 | 日常笔记→选中即卡→每周看统计→烂卡重写 |
| P3 语言学习者 | 大量重复但要不无聊 | 听写/打字题型、滑卡、TTS、激励 | 词句入库→听写刷→连胜保持 |
| P4 课程与专业学习者 | 材料、目标、练习和复盘要连起来 | 学习包、目标矩阵、应用练习、来源回链 | 课程材料→诊断→分段学习→正式复习→应用检查 |
| P5 内容作者/教师 | 内容能批量创作、版本更新和分享 | 字段模板、表格制卡、审核、差异与分享包 | 课程/资料→模板→审核→发布→版本维护 |
| P6 长期知识维护者 | 多年积累仍可迁移、检索和恢复 | 内容生命周期、数据健康、互通、备份 | 捕获→维护→迁移→跨工具复用→恢复 |
| P7 隐私与离线用户 | 不上传原文，也能在弱网和移动端学习 | 本地优先、离线降级、可访问性、可恢复 | 本地材料→本地卡片→离线复习→可验证备份 |

**画像预设包**（设置的第一个控件）：备考模式 / 笔记模式 / 语言模式 / 自定义。一个预设 = 一组模块开关 + 参数默认值。开关永远可微调——预设只改默认，不锁行为。

## 3. 设计原则

1. **内核权威、全链路覆盖**：正式调度、数据和官方已做的能力优先以内核为权威；插件覆盖从材料到应用的完整学习流程。
2. **数据不锁**：当前卡片本体以思源块 + 内核 riff/V2 库为权威；插件私有数据（revlog/计划/AI 批次）全部可导出，跨工具能力通过迁移契约扩展。
3. **默认轻，按需长**：新装只开核心三件（复习/统计/管理），其余模块按画像或手动点亮。
4. **渐进披露**：新手 5 分钟内能完成"制卡→复习 3 张→看到第一格热力图"；高级能力（AST 搜索、预设组、考试计划）藏在二级。
5. **双轨可降级**：每个 V2 能力都有 riff 兜底；能力检测驱动 UI 显隐，绝不因内核版本白屏。
6. **键鼠优先，触屏不缺**：桌面全快捷键（评分/撤销/跳过/回看），移动端手势+大按钮等价。
7. **原生观感**：全 b3 变量与内置组件类；入口长在思源体内（块菜单/面包屑/命令面板），不强加新世界观。
8. **宽容解析**：对外部数据（内核响应、V2 契约、打卡插件数据）宽容读取，缺字段静默降级，统计旁路永不阻塞主流程。
9. **生态互通**：向 eventBus 广播标准事件（复习完成/连击/制卡），供打卡、复盘、拾遗消费；能复用别人的正式数据就不另建事实源。
10. **AI 辅助而非事实源**：AI 可参与捕获、理解、制卡、练习、应用、维护、报告和 Agent 编排，但输出永远是可追溯、可编辑、可拒绝的候选；正式卡片事实、评分和 due 仍由用户与内核掌握。
11. **覆盖优先、分层交付**：凡是已被用户场景验证且适合本地优先的能力，都进入能力地图；优先级决定实现窗口，不决定是否属于产品目标。
12. **能力可插拔**：题型、语言、媒体、课程、生态和未来云能力都以模块/能力包接入，缺失时核心复习仍可用。
13. **后置可追踪**：暂时做不到的能力记录依赖、替代路径、退出条件和复评触发，不用“明确不做”掩盖未解决问题。
14. **本地隐私与逐任务同意**：AI 默认优先使用思源 AI 配置；自定义端点、本地模型和 Agent 都必须声明读取范围、外发范围、成本和保存期。任何原文、卡面、媒体或联系人外发都必须明确同意。
15. **统一 AI 调度面**：所有模块和思源 Agent 共用 TaskRegistry、ContextPack、PromptRegistry、ProviderRouter、SchemaValidator、EvidenceStore 和 AuditSink；业务 UI 不得各自直调模型或复制提示词。

## 4. 系统分层（自上而下）

```
L4 生态联动    打卡 · 复盘 · 拾遗 · eventBus 事件契约
L3 呈现层      UI Kit（src/ui/kit/，docs/16）· 复习面板 · 闪卡中心 · 向导与对话框 · 移动端
L2 领域模块    制卡工作流 · 会话引擎 · 题型系统 · 统计消费端 · 考试规划 · 激励 · Anki桥
L1.5 AI 编排层  TaskRegistry · ContextPack · PromptRegistry · ProviderRouter · SchemaValidator · EvidenceStore · Agent Bridge
L1 网关层      FlashcardGateway 统一接口
               ├─ RiffGateway（3.8.x，17 个 /api/riff/*）
               └─ V2Gateway（3.9.0+，/api/flashcard/* + getRenderModel）
L0 内核能力    内核 riff / 闪卡 V2 / FSRS / AnkiConnect / 思源 AI / 思源 Agent / Protyle 渲染
```

- **L1 与 L1.5 是扩展性的核心**：数据访问永远只面对 `FlashcardGateway`，AI 请求永远只面对 AI 编排层（见 14），Agent 与 UI 共用同一注册、执行、审计和撤销链；内核或模型怎么变都只改适配器。
- **L2 模块互相独立**，只依赖 L1 与事件总线；模块间禁止直接调用，走事件或显式服务注入。

## 6. 信息架构

### 6.1 入口矩阵

| 入口 | 行为 | 平台 |
|---|---|---|
| 顶栏图标 **左键** | 直接开始复习（最高频动作零层级） | 桌面+移动 |
| 顶栏图标 **右键** | 菜单：闪卡中心/开始复习/设置 + V2 状态徽章 + 今日到期摘要 | 桌面 |
| 顶栏图标 **角标** | 今日到期数（心跳刷新，移动端降级为菜单项文字） | 桌面 |
| 命令面板 | 打开闪卡中心 / 开始复习（默认热键）/ 制卡 | 全平台 |
| 块右键菜单 | 添加到卡组 / 快速制卡 / 卡片信息 / 移除卡片 | 桌面+移动 |
| 块图标菜单 | 卡片信息（reps/lapses/到期/所属） | 桌面 |
| 编辑器面包屑按钮 | 复习本文档（对齐 ZY 验证的交互） | 桌面 |
| 移动端悬浮球 | 复习（可拖动/置顶，与胶囊启动器拼合） | 移动 |

### 6.2 一级界面（3 个）

1. **复习面板**（Tab，桌面可停靠/移动全屏）——学习的发生地
2. **闪卡中心**（Tab，内置二级导航）——总览 / 管理 / 考试 / 数据，四个子页
3. **对话框族**——设置、AI 制卡向导、卡片详情、改期、批量确认

### 6.3 状态可见性

顶栏角标（到期数）→ 闪卡中心顶部常驻条（V2 状态 + 今日目标进度）→ 各子页空态引导。三层信息各管一件事，不互相重复。

## 7. 与官方 V2 的跟随策略

| 触发器 | 动作 |
|---|---|
| 3.9.0 beta 发布 | v0.9 冻结 riff 功能面；V2Gateway 按 beta 契约实现并打开内部开关 |
| 3.9.0 stable 发布 | v1.0：统计/管理/撤销切 V2Gateway；riff 保留兜底；发布"V2 兼容公告" |
| 官方新增端点 | 评估进 Gateway 能力矩阵；能用官方的不自建 |
| 官方 V2 卡型机制稳定 | M4 题型以 `plugin:lv-cards:*` 注册为首批第三方卡型 |

兼容承诺：`minAppVersion 3.8.0`；3.8 用户获得复习面板+本地统计；3.9 用户自动升级为官方数据源+题型扩展。

## 9. 扩展预留（设计期就锁定的口子）

1. **Gateway 接口**（14）：内核变更只改适配器；新端点=能力矩阵加一行。
2. **卡型注册契约**（14）：`registerCardType` 双实现（3.8 内部渲染 / 3.9 官方 V2 桥接），题型永远可插拔。
3. **模块注册契约**（14）：新功能=新模块（id/依赖/画像/阶段），注册即被设置面板、画像预设、事件系统自动纳管。
4. **事件契约**（14）：`lv-cards:*` 主题命名空间，生态模块只听事件不互相 import。
5. **存储版本化**（14）：所有私有 JSON 带 `version` 字段 + 迁移函数表，字段只增不删。
6. **画像系统开放**：预设包是纯数据（模块开关+参数快照），用户可导出分享，未来可做"社区画像"。
